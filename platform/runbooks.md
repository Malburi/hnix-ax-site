# 런북 — 승인 후 실행하는 조치

유지보수 현장의 장애 조치는 대부분 정해져 있다. 실패한 배치를 다시 돌리고, 캐시를 비우고, 멈춘 서비스를 다시 띄운다. 런북 실행기는 이런 조치를 미리 등록해 두고, **다른 사람이 승인한 뒤에만** 실행한다. 사람이 화면에서 요청해도, 경보 진단 에이전트가 원인을 좁힌 뒤 요청해도 같은 도구와 같은 승인함을 지난다.

> 기본은 꺼져 있다. 설정 파일에서 `runbooks.enabled` 를 켜고, 서버에서 프로그램을 실행하는 명령 런북까지 쓰려면 `runbooks.allowCommand` 도 켠다.

## 흐름

1. 관리자가 런북을 등록한다 — 이름, 설명, 종류(명령·HTTP), 실행 정의, 매개변수, 위험도.
2. 허브에 도구 `runbook__<이름>` 이 생긴다. 점검 명령이 있으면 `runbook__<이름>_check` 도 생긴다.
3. 운영자(또는 에이전트)가 값과 사유를 넣어 실행을 요청한다 → 승인 번호가 생긴다.
4. 다른 관리자가 MCP 허브 → 승인함에서 인자와 사유를 보고 승인한다. 자기 요청은 스스로 승인할 수 없다.
5. 요청자가 같은 값으로 다시 요청하면 실행된다. 에이전트가 요청한 것이면 승인 뒤 자동으로 이어 돈다.
6. 실행 기록에 요청자·승인자·인자·결과·출력이 남는다.

| 단계 | 승인 | 쓰임 |
|---|---|---|
| 점검 `_check` | 필요 없음 | 실제로 바꾸지 않고 확인만 — 예: `ansible-playbook --check`, 배치 상태 조회 |
| 실행 | 매번 필요(한 번 승인 = 한 번 실행) | 실제 조치 |

## 안전장치

- **승인 두 겹** — 허브 정책 "런북 실행은 사람 승인"을 기동할 때 만들고, 실행기도 직접 '방금 이 사람·이 값으로 쓰인 승인'이 있는지 본다. 누가 정책을 지우거나 꺼도 승인 없이는 실행되지 않는다.
- **셸을 거치지 않는다** — 명령은 인자 배열로 실행한다. `{{job}}` 자리에 들어간 값은 인자 하나로만 쓰이고, 실행 파일 자리에는 매개변수를 넣을 수 없다.
- **값 형식 검사** — 매개변수마다 허용할 문자(정규식)나 선택지를 정한다. 공백이나 `.*` 처럼 넓은 형식은 등록부터 거절한다. 형식이 틀린 값은 승인함에 올라가지도 않는다.
- **시간 제한** — 1~1800초. 넘기면 강제 종료하고 '시간 초과'로 남긴다.
- **최소 환경** — 명령에는 PATH 외의 환경 변수(비밀값 등)를 넘기지 않는다.
- **HTTP 런북** — 주소에 들어가는 값은 URL 인코딩, 본문은 JSON 이스케이프. 호스트 자리에는 매개변수를 넣을 수 없다.

## 등록 예

```json
{
  "name": "batch_rerun",
  "title": "배치 재실행",
  "description": "실패한 야간 배치를 다시 돌린다",
  "kind": "command",
  "spec": {
    "argv": ["/opt/batch/bin/rerun.sh", "{{job}}"],
    "checkArgv": ["/opt/batch/bin/rerun.sh", "--check", "{{job}}"],
    "cwd": "/opt/batch",
    "timeoutSec": 300
  },
  "params": [{ "name": "job", "description": "배치 ID", "pattern": "^[A-Z0-9_]{2,40}$" }],
  "risk": "medium"
}
```

HTTP 런북은 `spec` 에 `method`·`url`·`body`(JSON 문자열 템플릿)·`checkUrl` 을 쓴다. 사내 배치 스케줄러나 자동화 도구(Ansible AWX, Jenkins 등)의 API를 부르는 방식이 운영 서버에 직접 명령을 실행하는 방식보다 권한 관리가 쉽다.

## 경보 진단 에이전트와 함께

[에이전트 트리거](/platform/agents.md)의 경보 진단 템플릿으로 만든 에이전트의 허용 도구에 쓸 런북(`runbook__이름`)을 더하면, 에이전트가 경보를 받아 원인을 좁히고 맞는 런북을 요청한다. 실행은 사람이 승인할 때까지 멈춰 있다가 승인되면 이어 돈다. 자동화하되 조치 결정은 사람이 한다.

## 실행 기록

| 항목 | 내용 |
|---|---|
| 요청·승인 | 요청자, 승인 번호, 승인자, 사유 |
| 실행 | 검사를 통과한 인자, 점검 여부, 시작 시각, 소요 시간 |
| 결과 | 성공·실패·시간 초과, 종료 코드(HTTP 는 상태 코드), 출력 끝 8000자 |

관리자·감사자는 전체를, 그 외 사용자는 자기 요청만 본다. 런북을 지워도 기록은 남는다.
