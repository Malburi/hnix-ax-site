# 에이전트 평가 — 고칠 때마다 같은 시험

에이전트의 지시문·모델·도구를 바꾸면 어떤 질문에는 좋아지고 어떤 질문에는 나빠진다. 에이전트 평가는 **시험 문항**을 정해 두고 고칠 때마다 다시 돌려, 이전 평가와 문항별로 비교한다. 에이전트와 자동화 흐름 모두 대상이다. 메뉴 **AI 통제 → 에이전트 평가**, 또는 에이전트 화면의 **평가** 단추.

> 모델 별칭끼리 견주는 것은 [모델 평가](/platform/eval.md)다. 에이전트 평가는 같은 모델이라도 **에이전트 설정 전체**(지시문·도구·턴)를 잰다.

## 문항

문항 하나는 **입력**(에이전트면 문장, 흐름이면 입력 변수)과 **확인 항목** 몇 개다. 모든 확인 항목이 맞아야 통과하고, 점수는 확인 항목 점수의 평균이다.

| 확인 항목 | 예 |
|---|---|
| 포함 · 불포함 글자 | 답에 "재직"이 있어야 한다 / "주민번호"가 없어야 한다 |
| 정규식 | `SR-\d{4}` — 답에 서비스 요청 번호가 있다 |
| 쓴 도구 · 쓰지 말아야 할 도구 | `pmsx__srs` 를 불렀다 / 범위 밖 질문에는 도구를 안 쓴다 |
| 도구 호출 수 · 턴 수 · 시간 상한 | 도구 0회, 4턴 이하, 120초 이하 |
| 모델 채점 | 기준 문장("한국어로, 요청 번호와 처리 방향이 있다")과 심판 모델 별칭 — 0~1 점 |

문항은 화면에서 쓰거나 JSON 으로 가져온다. 실행 기록의 **평가 문항으로 저장**은 그 실행의 입력·출력·쓴 도구로 문항 초안을 만든다.

## 실행

- **평가 실행**은 문항을 차례로(동시 1~3개) 돌린다. 실행은 **내 권한**이다.
- 승인이 필요한 도구나 사람 확인에 닿으면 승인 요청을 올리지 않고 그 문항을 '승인 필요로 멈춤'으로 남긴다. 세트 설정으로 통과로 볼 수도 있다.
- 결과: 통과율 · 평균 점수 · 평균 지연과 p95 · 토큰 · 승인 필요 · 실행 오류, 문항별 확인 항목 결과와 이유.
- 문항마다 **디버거** 단추로 그 문항에서 에이전트가 실제로 한 일(모델·도구 단계)을 연다.
- 실행마다 평가한 설정(지시문·모델 별칭·도구·최대 턴, 흐름이면 판)과 해시를 남긴다.

## 비교

**이전과 비교**는 두 실행의 통과율·점수·지연·토큰 차이와, 문항마다 좋아짐·나빠짐·같음을 보여 준다. 두 실행 사이에 바뀐 설정(지시문·모델·도구)도 표시한다. 설정이 같은데 결과가 다르면 모델 답이 흔들리는 것이다. 작은 사내 모델일수록 문항으로 재야 하는 이유다.

## 밤마다 회귀 평가

MCP 도구 `evals__list` · `evals__run` · `evals__run_status` 가 있다. [자동화 흐름](/platform/flows.md)에 이 도구를 넣고 예약 트리거를 걸면 매일 밤 평가를 돌리고, 통과율이 떨어지면 알림을 보내는 흐름을 만들 수 있다.

## API

| 경로 | 내용 |
|---|---|
| `GET/POST /api/v1/agent-evals/sets` | 세트 목록·만들기(`agentId` 또는 `flowId`) |
| `POST /api/v1/agent-evals/sets/<id>/runs` | 실행(`?wait=true`) |
| `GET /api/v1/agent-evals/runs/<id>/results` | 문항별 결과 |
| `GET /api/v1/agent-evals/runs/<id>/compare?base=` | 비교 |
| `GET /api/v1/agent-evals/sets/<id>/export` | 내보내기(JSON) |
