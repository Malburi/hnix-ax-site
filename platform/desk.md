# 현업 창구 (L1 셀프서비스)

현업 사용자가 웹·메신저·메일로 물으면 운영 매뉴얼과 과거 처리 사례를 근거로 답한다. 근거가 없으면 모른다고 하고, 사용자가 확인하면 대화 기록을 붙여 티켓으로 넘긴다.

## 답하는 방식

1. **근거 찾기** — 창구에 지정한 문서 컬렉션에서 상위 4개, 유사 사례 도구(`pmsx__similar`)로 비슷한 KB·종료 SR 상위 3개를 찾는다. KB는 본문, SR은 요청과 공개 코멘트까지 읽는다.
2. **근거 안에서만 답하기** — 자료마다 번호를 붙여 모델에 주고, 답 문장에 `[1]`처럼 번호를 달게 한다. 번호를 하나도 못 대면 '확신 없음'으로 보고 담당자 접수를 권한다.
3. **근거가 없으면** — 모델을 부르지 않고 "답을 찾지 못했습니다"라고 한다.
4. **마무리** — 사용자가 **해결됐어요**를 누르면 자동 해결로 센다. **담당자에게 넘기기**를 누르면 메모를 덧붙여 접수한다.

질문 안의 지시는 따르지 않고, 비밀번호·개인정보를 알려 달라거나 시스템을 직접 바꿔 달라는 요청에는 응하지 않는다. 모델 호출은 창구의 실행 계정으로 게이트웨이를 지나므로 개인정보 가명화·데이터 등급·예산이 그대로 적용된다.

## 담당자 접수

| 방식 | 하는 일 |
|---|---|
| PMS-X SR | 허브에 등록된 PMS-X 서비스 계정으로 SM 프로젝트에 SR을 만든다. 요청자 이름·연락처, 대화 기록, AI가 참고한 자료, 사용자 메모가 본문에 실린다. 계정은 그 프로젝트의 운영자 이상이어야 한다 |
| 고객 ITSM 웹훅 | 접수 주소로 JSON을 보낸다. 응답의 `number`·`ticketId`·`id`를 접수 번호로 쓴다 |
| 플랫폼 접수함 | 플랫폼 대화 기록에 접수로 표시한다(ITSM 연결 전) |

이미 넘긴 대화를 다시 넘기면 같은 번호를 돌려준다. PMS-X 커넥터의 MCP 도구는 여전히 읽기 전용이고, SR 등록은 사용자가 확정한 이 동작에서만 일어난다.

## 채널

| 채널 | 주소 | 비고 |
|---|---|---|
| 웹 | `/desk/<주소 이름>` | 로그인(SSO 포함). 포털에는 `?embed=1`로 iframe |
| 메신저 봇·메일 게이트웨이 | `POST /desk-hooks/<창구 ID>` | `X-HNIX-Token: hxd_…`. 본문 `{text, user:{id,name,email}, threadId}` |
| Teams 나가는 웹훅 | `POST /desk-hooks/<창구 ID>/teams` | HMAC 서명 확인. 4.5초 안에 못 끝나면 "확인 중"으로 답하고 늦은 답장 주소로 이어서 보낸다 |

메신저에서는 같은 스레드의 다음 말이 같은 대화로 이어지고, **해결** 또는 **접수** 한 마디로 마무리한다.

```bash
curl -X POST "http://ax-platform:8700/desk-hooks/<창구 ID>" \
  -H "X-HNIX-Token: hxd_…" -H "content-type: application/json" \
  -d '{"text":"비밀번호 초기화는 어떻게 하나요?","user":{"name":"홍길동","email":"hong@corp.example"},"threadId":"t-1"}'
```

## 성과

관리 화면에 창구마다 30일 문의 수, **자동 해결률**(사용자가 해결 표시), 답변률, 담당자 접수율, 답을 못 찾은 수가 나온다. 대화 기록은 상태별로 보고, 접수 실패 사유도 남는다. 대화는 보관 기간(`chat.retentionDays`)이 지나면 지운다.

> 키워드 검색은 조사를 뗀 줄기도 함께 찾는다("기본값을" → "기본값"). 임베딩 별칭을 둔 컬렉션이면 의미 검색까지 더해져 답을 찾는 비율이 높아진다.
