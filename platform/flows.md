# 업무 자동화 — 정해진 순서대로 실행

에이전트는 모델이 그때그때 다음 할 일을 고른다. 업무 중에는 순서가 정해져 있어야 하는 것이 많다. 분류하고, 갈래에 따라 다른 사람(또는 에이전트)에게 넘기고, 담당자가 확인한 뒤에만 끝내는 일이다. 업무 자동화는 이런 순서를 **캔버스에 그려 두고 그대로 실행**한다. 메뉴 **에이전트·자동화 → 업무 자동화**.

## 새 흐름 — 템플릿과 말로 만들기

**새 흐름**을 누르면 빈 캔버스 대신 어디서 시작할지 고르는 창이 열린다. 고른 것은 편집기에 '저장 안 된 새 흐름'으로 열리고, 저장해야 남는다. 편집기의 **템플릿 불러오기**도 같은 창이다.

<figure><img src="img/platform-flows-gallery.png" alt="새 흐름 — 어디서 시작할까요? 창. 위 말로 만들기 칸과 AI 모델·초안 만들기, 아래 준비된 흐름 카드 — 서비스 요청 분류·처리, 경보 → 진단 → 사람 확인, 주간 운영보고 초안, 문서 찾아 답 초안(필요한 것 꼬리표와 이걸로 시작), 빈 흐름에서 시작"><figcaption>새 흐름 — 말로 만들기 · 준비된 흐름(템플릿) · 빈 흐름</figcaption></figure>

| 템플릿 | 하는 일 |
|---|---|
| 서비스 요청 분류·처리 | 새 서비스 요청을 AI가 장애·문의·기타로 분류해 장애는 담당 에이전트, 문의는 지식 문서 검색 → **답변 초안**, 담당자 확인 뒤 끝낸다 |
| 경보 → 진단 → 사람 확인 | 모니터링 경보(웹훅)를 받아 진단 에이전트가 원인 후보를 정리하고(실패하면 AI가 간단 진단) 운영자가 확인한다 |
| 주간 운영보고 초안 | PMS-X 처리 기한 현황과 처리 중·새로 접수된 서비스 요청을 읽어 AI가 주간 운영보고 초안을 쓴다(예약 자동 실행에 알맞음) |
| 문서 찾아 답 초안 | 질문으로 지식 문서를 찾아 AI가 근거를 밝힌 답 초안을 쓰고, 담당자가 확인한 뒤 확정한다 |

템플릿은 서버가 준다(`GET /api/v1/flows/templates`). 모델·에이전트 칸에는 연 사람이 쓸 수 있는 첫 모델·에이전트가 들어가고, 연 사람에게 보이지 않는 도구는 카드에 미리 알려 준다.

**말로 만들기**는 하고 싶은 일을 한 문장으로 받아 AI가 단계 초안을 그린다(`POST /api/v1/flows/draft`, 저장하지 않음).

1. 모델에게 '단계 목록' JSON 을 쓰게 한다 — 시스템 조회·실행(도구), AI에게 묻기, 에이전트에게 맡기기, 사람 확인(승인), 값 정하기, 끝. 도구·에이전트는 **연 사람에게 보이는 것**만 목록으로 준다.
2. 받은 목록을 시작 → 단계… → 끝 으로 잇고 검증한다. 목록에 없는 도구·에이전트, 앞에서 정하지 않은 변수는 '고칠 곳'이다. 고칠 곳이 있으면 그 목록을 붙여 **한 번 더 묻고**, 둘 중 고칠 곳이 적은 쪽을 연다.
3. 사람 확인의 '거부'는 *거부됨* 끝으로 잇고, 쓰기 도구 앞에는 사람 확인을 두게 한다.

사내 작은 모델(3B급)도 견디게 하려고 **조건에 따라 나누기와 목록 하나씩 반복은 만들지 않는다**. 갈래·반복이 필요하면 편집기에서 단계 상자로 더한다. 모델 호출은 실행과 같은 게이트웨이 경로(부른 사람 권한·데이터 등급·예산·개인정보 가리기)로 간다.

## 단계(노드) 9종

단계 종류 이름은 하는 일로 붙어 있다. 실행 디버거에는 종류 꼬리표가 짧게(모델·도구·에이전트·나누기·반복·사람 확인·값 정하기) 붙는다.

| 단계 | 하는 일 |
|---|---|
| 시작 | 실행할 때 받을 입력값(이름·필수 여부)을 정한다. 실행할 때 화면·REST·MCP·트리거가 이 값을 넣는다 |
| AI에게 묻기 | 게이트웨이 별칭으로 모델에게 묻는다. 물을 글에 `{{title}}`·`{{category.type}}` 같은 앞 단계 값을 넣고, 답을 JSON 으로 받아 변수에 담을 수 있다 |
| 시스템 조회·실행(도구) | MCP 허브 도구를 부른다. 입력값은 JSON 템플릿(**입력값 틀 채우기**로 항목 이름을 채운다) |
| 에이전트에게 맡기기 | 이미 만든 에이전트를 흐름의 한 단계로. 안에서 부르는 도구도 같은 정책·승인을 지난다 |
| 조건에 따라 나누기 | 규칙(같다·포함·크다 등)마다 갈래, 나머지는 '그 밖에'. 규칙 대신 AI가 고르게 할 수도 있다 |
| 목록 하나씩 반복 | 목록의 항목마다 안쪽 단계를 돈다. 항목 수 상한이 있다 |
| 사람 확인(승인) | 승인함에 올리고 결정을 기다린다. 승인·거부 출구가 따로 있고, **실행한 사람은 스스로 승인할 수 없다** |
| 값 정하기 | 글이나 앞 단계 값으로 새 값을 만들어 변수에 담는다 |
| 끝 | 흐름의 결과(출력) |

**변수 넣기** — 글을 쓰는 칸마다 옆에 단추가 있다. 누르면 그 단계에서 쓸 수 있는 값만 나온다. 시작 입력과, 선을 거슬러 이 단계까지 닿는 앞 단계의 결과다(JSON 으로 받는 AI 답은 `category.type` 같은 필드까지, 반복 안쪽이면 지금 항목·`loop.number`·`loop.count`, 사람 확인 뒤면 승인 여부·결정한 사람·사유). 고르면 커서 자리에 `{{이름}}` 이 들어간다. 안내용이라 실행을 막지는 않는다.

저장할 때마다 검증한다. 끊긴 선, 빠진 값, 시작 노드가 둘인 것 등은 '고칠 곳'으로 표시하고, 고칠 곳이 남아 있으면 실행하지 않는다.

## 버전 기록과 공개

- 저장할 때마다 **버전**이 하나씩 쌓인다. 실행은 그때의 버전으로 돌고, **버전 기록**에서 이전 버전을 불러와 되돌릴 수 있다.
- 공개 범위는 에이전트와 같다. 나만 → 공유 요청(관리자 승인) → 공개. 공개된 흐름은 다른 사람이 보기·실행만 하고, 고치는 것은 만든 사람과 관리자다.

## 실행하는 곳

| 어디서 | 방법 |
|---|---|
| 화면 | 편집기의 **시험 실행** — 입력값을 넣고 돌리면 캔버스에 지나간 노드가 표시되고 아래에 실행 디버거가 뜬다 |
| REST | `POST /api/v1/flows/<id>/runs` `{input: {...}}` (`?wait=true` 면 끝날 때까지) |
| MCP | `flows__list` · `flows__run` · `flows__run_status` — IDE·Claude Code·다른 에이전트에서 |
| 트리거 | 웹훅(경보·CI)·예약(cron)·감시 — 에이전트 트리거와 같은 방식으로 흐름을 깨운다 |

모델은 게이트웨이(키·예산·개인정보 가림·데이터 등급), 도구는 MCP 허브(정책·승인·감사)를 지난다. 모두 **실행한 사람 권한**이다.

## 사람 확인이 있는 흐름

1. 현업 담당자가 흐름을 실행한다 → 사람 확인 노드에서 '승인 대기'로 멈춘다.
2. 관리자가 왼쪽 메뉴 **승인함**에서 확인할 내용(분류 결과·처리안)을 보고 승인하거나 거부한다.
3. 결정되면 흐름이 멈춘 곳부터 **자동으로 이어 간다**. 거부하면 거부 출구로 간다.

## 실행 디버거

실행 기록에서 실행을 열면 단계마다 한 줄씩 폭포형 시간 막대로 보인다. 모델·도구·나누기·사람 확인·에이전트 단계와 걸린 시간, 토큰이 나온다. 단계를 누르면 자세한 내용이 나오고, 실패한 단계가 있으면 '첫 오류로'로 바로 간다.

**자세히 기록**을 켜면(흐름 설정에서 늘, 또는 시험 실행 때 이번만) 단계 본문도 남긴다. 모델에 보낸 글과 답, 도구 입력값과 결과다. 본문은 게이트웨이 개인정보 규칙으로 가린 뒤 보관 기한(기본 7일, `agents.debugRetentionDays`)까지 둔다. 본문은 실행한 사람·관리자·감사자만 보고, 남의 본문을 열면 감사 기록이 남는다.

## 예시 — 서비스 요청 분류·처리

템플릿 '서비스 요청 분류·처리'는 새 서비스 요청을 AI가 장애·문의·기타로 분류하고, 장애는 담당 에이전트가 원인 후보를 정리하고, 문의는 지식 문서를 찾아 **답변 초안**(근거로 쓴 문서 이름을 끝에 밝힘)을 쓴다. 담당자가 처리안을 확인하면 끝난다.

담당자에게 보이는 확인 내용은 읽을 수 있는 글이다. 도구 결과 같은 값을 넣어도 승인함에는 JSON 원문 대신 '근거 n건' 번호 목록, '이름: 값' 줄로 바뀌어 보인다. AI에게 물을 글·도구 입력값·끝의 결과(다른 흐름·도구가 JSON 으로 읽음)는 원래 모양 그대로 간다.

## 평가와 함께

흐름도 [에이전트 평가](/platform/agent-eval.md)의 대상이다. 입력 변수를 문항으로 넣고, 쓴 도구·출력 글자·시간으로 채점한다. 실행 기록의 **평가** 단추는 그 실행으로 문항 초안을 만든다.
