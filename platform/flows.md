# 자동화 흐름 — 정해진 순서대로 실행

에이전트는 모델이 그때그때 다음 할 일을 고른다. 업무 중에는 순서가 정해져 있어야 하는 것이 많다. 분류하고, 갈래에 따라 다른 사람(또는 에이전트)에게 넘기고, 담당자가 확인한 뒤에만 끝내는 일이다. 자동화 흐름은 이런 순서를 **캔버스에 그려 두고 그대로 실행**한다. 메뉴 **AI 통제 → 자동화 흐름**.

## 노드 9종

| 노드 | 하는 일 |
|---|---|
| 시작 | 입력 변수(이름·필수 여부)를 정한다. 실행할 때 화면·REST·MCP·트리거가 이 값을 넣는다 |
| 모델 질문 | 게이트웨이 별칭으로 모델에게 묻는다. 프롬프트 템플릿에 `{{title}}`·`{{category.type}}` 같은 앞 단계 값을 넣고, 답을 JSON 으로 받아 변수에 담을 수 있다 |
| 도구 호출 | MCP 허브 도구를 부른다. 인자는 JSON 템플릿 |
| 에이전트 실행 | 이미 만든 에이전트를 흐름의 한 단계로. 안에서 부르는 도구도 같은 정책·승인을 지난다 |
| 조건 분기 | 규칙(같다·포함·크다 등)마다 갈래, 나머지는 '그 외'. 규칙 대신 모델에게 고르게 할 수도 있다 |
| 반복 | 목록의 항목마다 안쪽 노드를 돈다. 항목 수 상한이 있다 |
| 사람 확인 | 승인함에 올리고 결정을 기다린다. 승인·거부 출구가 따로 있고, **실행한 사람은 스스로 승인할 수 없다** |
| 변수 정하기 | 값을 만들어 변수에 담는다 |
| 끝 | 출력 템플릿 |

저장할 때마다 검증한다. 끊긴 선, 빠진 값, 시작 노드가 둘인 것 등은 '고칠 곳'으로 표시하고, 고칠 곳이 남아 있으면 실행하지 않는다.

## 판 기록과 공개

- 저장할 때마다 **판**이 하나씩 쌓인다. 실행은 그때의 판으로 돌고, 판 기록에서 옛 판을 불러와 되돌릴 수 있다.
- 공개 범위는 에이전트와 같다. 나만 → 공유 요청(관리자 승인) → 공개. 공개된 흐름은 다른 사람이 보기·실행만 하고, 고치는 것은 만든 사람과 관리자다.

## 실행하는 곳

| 어디서 | 방법 |
|---|---|
| 화면 | 편집기의 **시험 실행** — 입력값을 넣고 돌리면 캔버스에 지나간 노드가 표시되고 아래에 실행 디버거가 뜬다 |
| REST | `POST /api/v1/flows/<id>/runs` `{input: {...}}` (`?wait=true` 면 끝날 때까지) |
| MCP | `flows__list` · `flows__run` · `flows__run_status` — IDE·Claude Code·다른 에이전트에서 |
| 트리거 | 웹훅(경보·CI)·예약(cron)·감시 — 에이전트 트리거와 같은 방식으로 흐름을 깨운다 |

모델은 게이트웨이(키·예산·개인정보 가림·데이터 등급), 도구는 MCP 허브(정책·승인·감사)를 지난다. 모두 **실행한 사람 권한**이다.

## 사람 확인이 있는 흐름

1. 현업 담당자가 흐름을 실행한다 → 사람 확인 노드에서 '사람 확인 대기'로 멈춘다.
2. 관리자가 **MCP 허브 → 승인함**에서 확인할 내용(분류 결과·처리안)을 보고 승인하거나 거부한다.
3. 결정되면 흐름이 멈춘 곳부터 **자동으로 이어 간다**. 거부하면 거부 출구로 간다.

## 실행 디버거

실행 기록에서 실행을 열면 단계마다 한 줄씩 폭포형 시간 막대로 보인다. 모델·도구·분기·사람 확인·에이전트 단계와 걸린 시간, 토큰이 나온다. 단계를 누르면 자세한 내용이 나오고, 실패한 단계가 있으면 '첫 오류로'로 바로 간다.

**자세히 기록**을 켜면(흐름 설정에서 늘, 또는 시험 실행 때 이번만) 단계 본문도 남긴다. 모델에 보낸 글과 답, 도구 인자와 결과다. 본문은 게이트웨이 개인정보 규칙으로 가린 뒤 보관 기한(기본 7일, `agents.debugRetentionDays`)까지 둔다. 본문은 실행한 사람·관리자·감사자만 보고, 남의 본문을 열면 감사 기록이 남는다.

## 예시 흐름

편집기의 **예시 불러오기**는 '서비스 요청 분류·처리'를 그린다. 새 서비스 요청을 모델이 장애·문의·기타로 분류하고, 장애는 담당 에이전트가 원인 후보를 정리하고, 문의는 지식 문서를 찾는다. 담당자가 처리안을 확인하면 끝난다.

## 평가와 함께

흐름도 [에이전트 평가](/platform/agent-eval.md)의 대상이다. 입력 변수를 문항으로 넣고, 쓴 도구·출력 글자·시간으로 채점한다. 실행 기록의 **평가** 단추는 그 실행으로 문항 초안을 만든다.
