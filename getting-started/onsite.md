# 고객사 설치와 연결 점검

설치 패키지를 고객사 서버에 올린 뒤 첫 주에 할 일이다. 연동은 대부분 고객 쪽 계정·방화벽·웹훅이 있어야 끝나므로, 담당자(서버·DB, ITSM, GitLab, 모니터링, AI 조직 관리자)와 날짜를 잡고 아래 순서로 함께 확인한다. 확인은 플랫폼의 **관리 › 현장 연결 점검** 화면 하나로 한다.

## 순서

| # | 할 일 | 고객 쪽 준비 | 확인 |
|---|---|---|---|
| 1 | 설치·기동 — [설치 패키지](/platform/operations.md), PostgreSQL, `server.publicUrl`, `backup.time` | 서버·DB 계정, 서비스 계정 | `/readyz` 200, 점검 화면 '기본 설치' |
| 2 | 사내 계정 로그인 — LDAP(AD) 또는 OIDC(SSO) | 디렉터리 조회 계정 또는 SSO 앱 등록 | 사내 계정으로 로그인, 관리자 그룹 매핑 |
| 3 | 모델 — 사내 GPU 모델 서버([vLLM 꾸러미](/platform/eval.md)) 또는 조직 API 키 | GPU 서버, 외부 HTTPS 허용(클라우드 모델을 쓸 때) | 게이트웨이 시험 호출, 모델 평가 세트 점수 |
| 4 | PMS-X 연결 — MCP 허브에 PMS-X 서버(서비스 계정) 등록 | PMS-X 서비스 계정 | 점검 화면 '도구 서버' 연결 시험 |
| 5 | 고객 ITSM — [ServiceNow·Jira 연결](/platform/itsm.md), 웹훅 | 티켓 조회·수정 권한 계정, 웹훅 등록 권한 | 연결 시험(최근 하루 티켓), 시험 티켓 → SR 접수 → SR 처리 → 티켓 상태 |
| 6 | Git — [저장소 등록과 웹훅](/platform/productivity.md) | GitLab 관리자(Push·Merge request 이벤트, 비밀 토큰) | 시험 커밋 → 생산성 보고서에 SR 연결 |
| 7 | 모니터링 경보 — Alertmanager·Grafana·Zabbix 웹훅 → [에이전트 트리거](/platform/agents.md) | 모니터링 담당 | 시험 경보 → 진단 실행 기록 |
| 8 | 외부 AI 사용량 — [Claude 조직 Admin API·Copilot](/platform/enterprise-ai.md) | 조직 관리자가 만든 관리 키·토큰 | 연결 시험(받은 행 수) |
| 9 | 현업 창구 — 포털 iframe(`security.frameAncestors`)·Teams | 포털 담당, Teams 관리자 | 포털에서 질문 → 답변·접수 |
| 10 | AX-NAVI 조직 설정 — [묶음 배포](/axnavi/integration.md#조직-설정-배포) | 개발자 PC 의 `HNIX_AX_SERVER`·`HNIX_AX_KEY` | `axnavi org pull`, 점검 화면 '받아 간 PC' |
| 11 | 런북 — `runbooks.enabled`, 점검(dry-run) 런북부터 | 배치 스케줄러·자동화 도구 API 계정 | 점검 → 승인 → 실행 기록 |

모든 연동이 필요한 것은 아니다. 고객이 쓰지 않는 것은 점검 화면에 '안 씀'으로 남는다.

## 현장 연결 점검 화면

**관리 › 현장 연결 점검**(관리자·감사자). 영역마다 항목·상태·내용·할 일을 한 표로 보여 준다.

| 버튼 | 하는 일 |
|---|---|
| 다시 점검 | 이미 남은 기록만 읽는다 — 마지막 동기화, 마지막 웹훅 수신, 최근 하루 모델 요청 결과, 백업 시각. 외부로 나가지 않는다 |
| 연결 시험 포함 점검 | 관리자만. 실제로 붙어 본다 — MCP 서버 도구 목록 다시 받기, ITSM 최근 티켓 조회, 외부 AI 사용량 받기. 감사 로그에 남는다 |

| 상태 | 뜻 |
|---|---|
| 정상 | 연결됐고 최근 기록이 있다 |
| 확인 | 설정은 됐지만 아직 기록이 없거나(웹훅이 한 번도 안 옴 등) 권장 설정이 비었다 |
| 문제 | 마지막 시도가 실패했거나 꼭 있어야 할 것이 없다(켜진 모델 공급자 없음, 백업 없음) |
| 안 씀 | 등록하지 않은 연동 |

| 영역 | 보는 것 |
|---|---|
| 기본 설치 | 데이터베이스 종류, 접속 주소, 사내 계정 로그인, 백업(자동 시각·마지막 백업), 여러 대 운영 |
| LLM 게이트웨이 | 켜진 공급자마다 최근 하루 성공·실패와 마지막 오류 |
| 도구 서버(MCP 허브) | PMS-X·AX-NAVI·외부 MCP 서버의 마지막 도구 목록 받기, 오류 |
| 고객 ITSM | 연결마다 마지막 동기화·오류, 웹훅 설정 여부 |
| Git 저장소(생산성) | 저장소마다 받은 커밋 수, 마지막 웹훅 수신 |
| 외부 AI 사용량 | 원천마다 마지막 수집·오류 |
| 자동화 | 경보 웹훅 트리거(한 번도 안 온 것), 오류 난 트리거, 런북, 현업 창구의 접수처 |
| AX-NAVI 조직 설정 | 배포된 묶음, 최근 7일 받아 간 PC·키 |

같은 내용을 `GET /api/v1/admin/readiness`(연결 시험은 `?probe=1`)로 받을 수 있다. 인수 확인서나 주간 보고에 붙일 때는 JSON 을 저장해 둔다.

## 자주 막히는 곳

- **방화벽 방향** — 나가는 쪽(플랫폼 → ITSM·GitLab API·외부 AI 관리 API)과 들어오는 쪽(ITSM·GitLab·모니터링 → 플랫폼 웹훅)을 따로 연다. 웹훅은 보통 리버스 프록시 뒤 `https://<공개 주소>/itsm-hooks/…`, `/git-hooks/…`, `/hooks/…` 로 들어온다.
- **사내 인증서** — 고객 프록시가 HTTPS 를 다시 서명하면 Node 가 인증서를 믿지 못한다. 고객 루트 인증서를 PEM 으로 받아 서비스 환경 변수 `NODE_EXTRA_CA_CERTS` 에 지정한다.
- **웹훅이 안 온다** — 점검 화면에 '한 번도 안 옴'으로 남는다. 주소의 연결 번호, 토큰(로테이트 뒤 옛 토큰), 고객 시스템의 발송 기록을 순서대로 본다.
- **티켓은 오는데 SR 이 안 생긴다** — ITSM 연결의 PMS-X 서버·프로젝트, 서비스 계정의 SR 등록 권한을 본다.
- **시간대** — 서버 시간대가 다르면 SLA·일별 집계가 하루씩 밀린다. 서버를 고객 현지 시간대로 둔다.
