# 제품 조합과 함께 설치할 때

HNIX AX의 네 제품은 **각자 혼자서 완결**되고, 함께 있으면 **선택 연결**로 더 좋아진다. 어떤 연결을 켤지는 설치할 때 설정으로 정한다. 한 제품을 나중에 더하거나 빼도 다른 제품은 그대로 돈다.

## 상황별 조합

| 상황 | 들어가는 제품 | 혼자일 때 하는 일 | 나중에 더하면 |
|---|---|---|---|
| 운영 대행만 맡은 현장 | PMS-X | 서비스 요청·처리 기한·장애·지식 문서·월간 운영보고(AI 꺼짐) | Platform을 더하면 요청 분류 추천·유사 사례·현업 창구 |
| 사내 AI 통제가 먼저인 현장(요청은 고객 ITSM에 남김) | AX Platform (+ AX-NAVI) | 게이트웨이·사용량·도구 허브·문서 검색, 필요한 선택 모듈만 | PMS-X를 더하면 창구 접수처·생산성 보고서에 서비스 요청 연결 |
| 데이터 거버넌스가 급한 현장 | AX-DataLake | 수집·권한·가림·행 제한·계보·분석 | Platform을 더하면 AI 질문(게이트웨이)과 허브 경유 조회 |
| 개발 프로젝트(SI) | AX Platform + AX-NAVI (+ PMS-X) | 사용 허가·엔진 배포·게이트웨이 경유 코드 작업 | PMS-X As-Is 분석·구현 명세를 개발자에게 |
| 통합ITO 전부 | 네 제품 | 아래 권장 설정대로 연결 | — |

AX-NAVI(IDE·CLI)만은 혼자 돌지 않는다. 로그인해 사용 허가와 엔진을 AX Platform에서 받기 때문이다.

## 함께 설치할 때 권장 설정

### 1. 계정 — 고객사 디렉터리 하나에 각 제품이 직접

계정의 원본은 어느 한 제품이 아니라 **고객사 AD·SSO**다. 각 제품이 디렉터리에 직접 붙으므로, 한 제품이 없어도 다른 제품의 로그인은 그대로다.

| 제품 | 설정 | 첫 로그인 |
|---|---|---|
| AX Platform | `auth.ldap` 또는 `auth.oidc` | 계정이 생겨 기본 워크스페이스에 들어간다 |
| PMS-X | `pmsx.auth.ldap` — `auto-create: true`, `allowed-groups` | 계정이 생긴다(역할·프로젝트 없음 — 관리자가 프로젝트에 넣는다). 기본은 꺼짐 |
| AX-DataLake | `auth.ldap` 또는 `auth.oidc` + `auth.directory` — `autoCreate`, `allowedGroups`, `roleGroups`(그룹 → 관리자·엔지니어·분석가), 소속은 `orgAttr` | 기본은 관리자가 '사내 계정'으로 먼저 등록. `autoCreate` 를 켜면 계정이 생긴다(역할은 그룹, 없으면 분석가). 기본은 꺼짐 |

AD·SSO 는 선택이다. 어느 제품이든 켜지 않으면 지금처럼 그 제품의 자체 계정으로 로그인하고, 켜도 자체 계정(특히 관리자)은 그대로 쓸 수 있다 — 디렉터리가 멈췄을 때 들어올 길이다. 세 제품의 관리자 그룹을 같은 디렉터리 그룹으로 맞추면 권한 관리가 한 번에 끝난다. 자세한 것은 매뉴얼의 [계정 · 권한 · 로그인 연동](https://malburi.github.io/hnix-ax-manual/#/admin/accounts)에 있다.

### 2. 요청 창구 — 문은 하나로

현업 사용자에게 보이는 문은 하나만 둔다. 플랫폼 [현업 창구](/platform/desk.md)를 PMS-X 고객 포털이나 사내 포털에 넣고(`/desk/<주소 이름>?embed=1`), 못 푼 질문은 접수처로 넘긴다.

| 요청 기록의 원본 | 창구 접수 방식 | 필요한 모듈 |
|---|---|---|
| PMS-X | PMS-X 서비스 요청 | `desk` |
| 고객 ITSM(ServiceNow·Jira) | ITSM 연결 또는 웹훅 | `desk` (+ `itsm`) |
| 아직 없음 | 플랫폼 접수함 | `desk` |

### 3. 문서 — 한 곳에만 올린다

| 현장 | 문서의 원본 | 설정 |
|---|---|---|
| 레이크가 없다 | 플랫폼 문서함 | — |
| 레이크가 있다 | AX-DataLake 문서 묶음 | 플랫폼 `docs.lake`에 레이크 주소와 API 키(query 범위)를 넣으면 문서 검색·채팅·현업 창구가 레이크 문서도 함께 찾는다. [서버판](/getting-started/server-kit.md)은 설치가 자동으로 넣는다 |

레이크 문서에는 그 키를 만든 레이크 사용자의 권한(조회 권한·가림·행 제한)이 그대로 걸린다. 분석가 역할 사용자로 키를 만들기를 권한다. 같은 문서를 플랫폼과 레이크에 두 번 올리지 않는다. → [문서 검색](/platform/docs-rag.md#ax-datalake-문서-함께-찾기)

### 4. 모델 호출 — 통제 모드

개발자 PC의 AX-NAVI는 PC 공용 정책 `allowedRoutes: ["gateway"]`로 모든 호출이 게이트웨이를 지나게 한다. 개발자 본인 Claude 구독을 허용할지는 현장이 정한다. → [AI 연결 정책](/getting-started/architecture.md#ai-연결-정책)

### 5. 플랫폼 기능 — 필요한 모듈만

플랫폼은 설치본 하나에 **기반**(게이트웨이·사용량·도구 허브·문서 검색·AX-NAVI 사용 허가)과 **선택 모듈**이 들어 있다. 현장에 맞게 `modules`에서 켜고 끈다. → [기반과 선택 모듈](/platform/README.md#기반과-선택-모듈)

### 6. 성과 숫자 — 생산성 보고서에 모은다

[생산성 보고서](/platform/productivity.md)에 PMS-X 연결과 프로젝트를 고르면, 커밋·서비스 요청·AI 관여를 한 보고서로 본다. PMS-X가 없으면 고객 ITSM의 요청을 API(`/api/v1/delivery/work-items`)로 넣는다.

## 한 제품이 멈추면

연결은 모두 선택이라 멈춘 제품의 연결 기능만 빠지고 나머지는 계속 돈다.

| 멈춘 제품 | 빠지는 것 | 계속 도는 것 |
|---|---|---|
| AX Platform | 게이트웨이를 지나는 AI 호출(PMS-X AI 보조·레이크 AI 질문·통제 모드의 AX-NAVI 채팅), 현업 창구, 허브 도구 | PMS-X 운영 전부, 레이크 조회·분석, AX-NAVI의 색인·변경 리뷰 판정(모델 없이 도는 것 — 오프라인 기간 안에서) |
| PMS-X | 창구의 PMS-X 접수(실패 사유가 관리 화면에 남는다), `pmsx__*` 도구 | 플랫폼·레이크 전부, 창구 답변 |
| AX-DataLake | 레이크 문서 검색(검색 결과에 경고 한 줄), `datalake__*` 도구 | 플랫폼 문서만으로 검색·답변, PMS-X 전부 |
