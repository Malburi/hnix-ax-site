# 사용 허가 — 로그인과 기기 승인

AX-NAVI IDE 설치본은 **HNIX AX 플랫폼에 로그인해 승인받은 기기에서만** 동작한다. 설치 파일이 밖으로 새거나 몰래 배포돼도, 허가받지 않은 사람은 AI 채팅·스킬·판정 엔진을 쓸 수 없다. 스킬과 에이전트도 설치본에 들어 있지 않고, 로그인한 기기에 플랫폼이 내려 준다.

목표는 두 가지다.

- **밖에서 훔친 사본은 쓸모없게** — 로그인 전에는 모델 호출과 AX-NAVI 명령이 모두 막힌다. 이 검사는 릴리스 빌드에 박혀 있어 설정이나 환경 변수로 끌 수 없다.
- **안에서 새면 누가 흘렸는지 알게** — 기기마다 내려 주는 스킬·에이전트 문서에 보이지 않는 표식이 들어간다. 밖에서 발견된 문서를 플랫폼에 넣으면 어느 사람·기기로 받은 것인지 나온다.

## 처음 로그인하기

1. AX-NAVI IDE를 처음 열면 상태 표시줄 오른쪽에 **AX-NAVI 로그인**이 보이고, 채팅 위에도 "로그인이 필요합니다" 안내와 **[로그인]** 단추가 뜬다. 어느 쪽이든 누른다(명령 팔레트 › **AX-NAVI: 플랫폼 로그인 (이 기기 승인)**도 같다).
2. 브라우저에 플랫폼 승인 화면이 열린다. 평소 쓰는 플랫폼 계정으로 로그인한다(로컬 계정 또는 사내 LDAP).
3. 화면의 **승인 코드**가 IDE 알림에 뜬 코드와 같은지 확인하고 **이 기기 승인**을 누른다. 본인이 시작하지 않은 요청이면 **거절**한다.
4. 몇 초 안에 IDE 상태 표시줄이 **👤 내 이름**(계정 항목)으로 바뀌고, 스킬과 판정 엔진을 받아 온다.

| 화면 | 보이는 것 |
|---|---|
| IDE 알림 | `AX-NAVI 로그인 — 브라우저에서 코드 BCDF-GHJK 를 확인하고 승인하세요` |
| 플랫폼 승인 화면(`/axnavi/activate`) | 승인 코드, 계정, 기기 이름·운영체제, 프로그램과 버전, 요청 주소, 만료 시각, 내 허가와 등록한 기기 수. 아래에 **내 기기** 목록과 폐기 버튼(메뉴 **내 AX-NAVI 기기**) |
| IDE 상태 표시줄 | 로그인 전 `AX-NAVI 로그인` · 로그인 뒤 계정 항목 `👤 이개발` · 플랫폼에 잠시 닿지 않으면 `(오프라인)`. 변경 리뷰 항목은 따로 `리뷰`로 보여 계정과 헷갈리지 않는다 |

로그인 정보는 이 PC에만 남는다. 기기 비밀은 운영체제 비밀 저장소(Windows DPAPI)에, 사용권 토큰(1시간짜리)은 메모리에만 둔다. 플랫폼에는 기기 비밀의 해시만 저장한다.

## 로그인하면 받아 오는 것

| 받는 것 | 내용 | PC에 남는 형태 |
|---|---|---|
| **스킬·에이전트** | `/find`, `/flow`, `/impact`, `/review-sql`, `/security-scan`, `/safe-modify`, `/harness-init` 등 26개와 하위 에이전트 | 기기 비밀 저장소의 키로 암호화한 캐시 |
| **판정 엔진** | 변경 리뷰·보안 점검·단계 게이트·색인·환경 진단을 계산하는 엔진 | `globalStorage/engine/<버전>` 폴더. 바뀌었을 때만 다시 받는다 |

판정 엔진을 IDE가 직접 돌리므로 **AX-NAVI CLI나 Node.js를 따로 깔지 않아도 된다.** 엔진은 IDE 실행 파일을 Node로 돌리고, 스킬이 부르는 Python은 PC에 있으면 그것을, 없으면 IDE에 들어 있는 Python(3.12, SQLAlchemy 포함)을 쓴다. 채팅의 명령 실행과 새 터미널에서 `axnavi`, `node`, `python`, `python3` 명령이 그대로 통한다.

플랫폼에 잠시 닿지 않아도 플랫폼이 정한 기간(기본 3일)까지는 받아 둔 스킬과 엔진으로 계속 쓴다. 그 기간이 지나면 다시 로그인해야 한다.

## 잠기는 때

| 상황 | IDE |
|---|---|
| 로그인 전 | 모델 호출, 슬래시 명령, 변경 리뷰·보안 점검·게이트가 모두 막힌다 |
| 관리자가 허가(좌석)를 회수 | 사용권 토큰을 새로 받을 때(토큰 수명, 기본 1시간 안) 잠기고, 받아 둔 스킬·엔진을 지운다 |
| 사용자가 내 기기 목록에서 폐기, 또는 관리자가 기기 폐기 | 그 기기만 잠긴다 |
| **AX-NAVI: 로그아웃 (이 기기 승인 지우기)** | 이 기기 승인을 지우고 받아 둔 스킬·엔진도 지운다 |
| 오프라인 기간을 넘김 | 플랫폼에 다시 닿아 확인될 때까지 잠긴다 |

현재 상태는 상태 표시줄의 계정 항목을 누르거나 **AX-NAVI: 계정·사용 허가 상태**로 본다 — 플랫폼 주소, 사용자, 기기, 엔진 위치(PC/서버), 토큰 만료(오프라인이면 캐시로 쓸 수 있는 기한)가 나온다.

로그인이 풀리거나 허가가 회수되면 IDE 는 같은 요청을 자동으로 되풀이하지 않는다. 채팅에 사유와 함께 **[로그인]**·**[다시 로그인]**, 사내 모델 키가 맞지 않으면 **[키 다시 받기]**(명령 **AX-NAVI: 키 다시 받기 (사내 모델·MCP 허브)**)가 뜬다. 네트워크가 끊긴 것인지, Claude Code 구독 로그인이 풀린 것인지도 한국어로 나눠 알려 준다.

## 관리자 — 허가와 기기

플랫폼 관리자는 메뉴 **AX-NAVI 사용 허가**(`/axnavi-seats`)에서 관리한다.

| 할 일 | 방법 |
|---|---|
| 허가 주기 | 사용자를 골라 허가(좌석)를 준다. 메모(소속·과제)를 남길 수 있다 — 칸을 벗어나거나 Enter 를 누르면 저장되고 알림이 뜬다 |
| 엔진 위치 정하기 | **PC(IDE에 자동 설치)** — 기본. 모든 스킬과 단계 게이트를 쓴다 · **서버만** — PC에 엔진을 두지 않는다(아래) |
| 회수 | 허가를 거두면 그 사람의 모든 기기가 잠긴다. 누르면 "연결된 기기 2대의 연결이 바로 끊깁니다 … 엔진 설정과 메모도 지워집니다. 되돌릴 수 없습니다"처럼 결과를 적은 확인 창이 먼저 뜬다. 다시 허가해도 끊긴 기기는 IDE 에서 새로 로그인해야 한다 |
| 기기 보기·폐기 | 사람별 등록 기기(이름·운영체제·마지막 확인 시각)와 폐기 |
| 유출 문서 추적 | 밖에서 발견된 스킬·에이전트 문서를 붙여 넣으면, 표식으로 받은 사람과 기기를 찾는다 |

모든 승인·회수·폐기·추적은 감사 기록에 남는다. 설정(`hnix-ax.yaml`)으로 정하는 값은 다음과 같다.

```yaml
axnavi:
  seats: listed        # listed — 허가받은 사람만 · all — 로그인하는 모든 사용자
  maxDevices: 2        # 한 사람당 기기 수
  licenseMinutes: 60   # 사용권 토큰 수명(분) — 회수가 반영되는 최대 시간
  offlineDays: 3       # 플랫폼에 닿지 않아도 쓸 수 있는 날수
  defaultEngine: local # 새 허가의 엔진 위치 — local(PC) · server
```

## 서버 엔진 — PC에 엔진을 두지 않을 사람

엔진 위치를 **서버만**으로 정한 사람은 PC에 판정 엔진을 받지 않는다. 외주 인력처럼 엔진과 스킬 원본을 PC에 두면 안 되는 경우에 쓴다.

| 기능 | 서버 엔진에서 |
|---|---|
| 색인 질의(`QueryIndex`) | 플랫폼 MCP 허브의 색인 도구로 |
| 변경 리뷰 | PC의 `git diff`를 플랫폼으로 보내 판정받는다 |
| 보안 점검·색인 만들기 | 플랫폼이 저장소의 Git 사본으로 돌린다 |
| 스킬 | 서버 도구만으로 도는 12개(`/find`, `/flow`, `/impact`, `/review-sql`, `/security-scan` 등) |
| 쓸 수 없는 것 | 단계 게이트, 환경 진단, PC에서 빌드·검증하는 스킬(`/safe-modify`, `/harness-init` 등 14개) |

## 플랫폼 주소 정하기

IDE는 다음 순서로 플랫폼 주소를 찾는다. 앞에서 찾으면 뒤는 보지 않는다. 보통은 배포할 때 PC 공용 정책에 넣어 둔다.

1. PC 공용 정책 `%ProgramData%\axnavi\policy.json`의 `platform` — 관리자가 정한 주소라 사용자가 바꿀 수 없다
2. 설정 `axnavi.platform.url` — **AX-NAVI 연결**로 주소를 넣으면 IDE 가 여기에 저장한다
3. 환경 변수 `HNIX_AX_SERVER`
4. 설치할 때 넣은 주소 — 설치 화면에서 넣었거나 `/SERVER=` 로 준 주소(설치 폴더의 `axnavi.json`)

```json
{ "platform": "http://ax.hd.local:8700", "allowedRoutes": ["subscription", "gateway"] }
```

## 점검 결과

2026-11-01, Node·Python·AX-NAVI CLI가 없는 PC에 IDE만 깔고 Spring·MyBatis 인사 시스템 예제로 스킬을 돌렸다. 모델은 개발자 본인의 Claude 구독이다.

| 스킬 | 결과 |
|---|---|
| `/harness-init` | 색인, 분석 요약, 하네스 조립, 패턴 추출, 기계 검증, 하위 에이전트 5개까지 끝까지 완료. `CLAUDE.md`·`AGENTS.md`·로컬 스킬·패턴 생성 |
| `/find` | 발령 등록 흐름(화면 → JS → 컨트롤러 → 서비스 → 테이블 INSERT)을 색인 검색으로 정확히 찾음 |
| `/impact` | 테이블에 컬럼을 더할 때 위험도 2/10, 쓰는 SQL 4건, NOT NULL로 만들 때의 위험까지 |
| `/review-sql` | 사원 목록 SQL을 사용처·인덱스·N+1·인젝션 등 8개 항목으로 점검 |
| `/security-scan` | 파일 49개, 지적 0건(원문 대조로 확인) — 보고서 파일 생성 |
| `/flow` | 발령 확정 버튼부터 DB 반영까지 추적, 상세 보고서 생성 |
| `/safe-modify` | 요청의 전제(없는 컬럼)가 틀린 것을 사전 분석에서 잡아 사람에게 되묻고, 소스는 바꾸지 않음 |
