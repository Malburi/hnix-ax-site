# SDLC 산출물과 단계 게이트

요구 → 설계 → 개발 → 테스트 단계마다 필요한 산출물을 조직 양식으로 만들고, 다음 단계로 넘어가도 되는지 판정한다. 양식 생성과 판정은 AI를 부르지 않는다. 서술은 사람이 쓰거나, `sdlc-docs` 스킬("설계서 써줘")이 근거를 붙여 채운다.

## 산출물

```bash
axnavi doc new all          # docs/sdlc/ 에 양식 생성
axnavi doc list             # 필수 절 작성 · 승인 상태
axnavi adr new "주문 취소 사유를 코드 테이블로 관리"   # docs/adr/NNNN-제목.md
```

| 단계 | 산출물 | 자동으로 채우는 것 |
|---|---|---|
| 요구 | 프로젝트 정의서, 요구사항 명세서 | 규모, 스택 |
| 설계 | 설계서, 개발 표준, ADR | 모듈, API 경로, 상위 테이블, 코드 패턴 |
| 개발 | 진행 기록서 | 게이트 이력 |
| 테스트 | 품질 검증서 | 보안 점검 요약 |

자동 항목은 색인과 리포트에서 AI 없이 채운다. 사람이 써야 하는 절은 비워 둔다.

## 조직 양식

양식은 이 순서로 찾는다.

1. 프로젝트 `.axnavi/templates/<종류>.md`
2. 조직 공용 폴더 `AXNAVI_TEMPLATES_DIR`
3. 내장 양식

양식 머리말의 `required:`에 적은 절이 작성 필수다. 회사 표준 양식을 한 번 넣어 두면 모든 프로젝트가 같은 목차로 산출물을 만든다.

## 단계 게이트

```bash
axnavi gate design            # 설계 단계로 넘어가도 되나
axnavi gate dev --record      # 판정을 진행 기록서 이력 표에 남김
```

| 단계 | 게이트가 보는 것 |
|---|---|
| `req` | 필수 절 작성(빠지면 STOP), 문서 승인(아니면 HOLD) |
| `design` | 위 + ADR 유무, 제안 상태 ADR, ADR 본문 |
| `dev` | 위 + `axnavi review` 결과 (STOP이면 STOP, HOLD면 HOLD) |
| `test` | 위 + 보안 점검 치명(STOP)·높음(HOLD) |

게이트는 앞 단계를 누적해서 본다. 종료 코드는 변경 리뷰와 같다(0 / 3 / 4).

```text
# 단계 게이트 — 설계 (design)
판정: STOP · 종료 코드 4
⛔ 요구  요구사항 명세서 작성   없음 — axnavi doc new srs 로 양식을 만든다
⛔ 설계  개발 표준 작성         없음 — axnavi doc new standards 로 양식을 만든다
✅ 설계  아키텍처 결정 기록     ADR 2건
⚠️ 설계  ADR 결정              제안 상태 1건: ADR-0002
```

## 작성된 것으로 보지 않는 절

- 양식 그대로인 절
- 자동 항목만 있는 절
- `(…)` 안내문이나 `확인 필요` 줄만 있는 절

문서 머리말의 `상태:`를 `승인`으로 바꾸는 것은 검토자의 몫이다. doc-syncer 에이전트는 변경에 아키텍처 결정이 있으면 ADR을 상태 `제안`으로 새로 쓴다. 기존 문서를 자동으로 고치지는 않는다.
