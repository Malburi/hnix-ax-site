# 설치와 첫 사용

## 1. 설치

**AX-NAVI IDE** (Windows x64)

1. AX Platform 에 로그인해 **내 연결 설정** › **개인 PC 설치 파일 받기** — 회사 코드 서명이 된 설치 파일(`HNIX-AX-PC-Setup-<버전>.exe`)을 실행한다. 관리자 권한은 필요 없다.
2. 같은 화면의 **AX-NAVI IDE 에서 열기** → IDE 가 '이 플랫폼에 연결할까요?'를 물으면 **연결** → 브라우저 승인 화면에서 **승인**.
3. 끝. IDE 가 플랫폼에서 이 PC 전용 연결(사내 모델 게이트웨이·사용량 기록·MCP 허브 키)과 AX-NAVI 엔진·스킬을 받아 스스로 설정한다. PC 에 Claude Code 가 있으면 Claude Code 의 사용량 전송과 MCP 허브(`hnix-ax`)도 넣는다. 키·환경 변수를 손으로 넣지 않는다.

설치 화면에서 회사 플랫폼 주소를 물으면 '내 연결 설정'에 보이는 주소를 넣는다(비워 두면 IDE 를 처음 열 때 묻는다).

버튼을 쓸 수 없으면 IDE 상태 표시줄의 **AX-NAVI 로그인**(또는 채팅 위 안내의 **[로그인]**)을 눌러 플랫폼 주소를 넣는다. 다른 플랫폼으로 바꾸려면 명령 **AX-NAVI: 플랫폼 로그인 — 다른 주소로**. 관리자가 PC 공용 정책으로 주소를 정해 둔 PC 에서는 이 명령의 다른 주소 입력이 보이지 않는다.

| 설치하면 | 위치 |
|---|---|
| 프로그램 | `%LOCALAPPDATA%\Programs\AX-NAVI IDE` |
| 바로가기 | 시작 메뉴, 바탕 화면 |
| 명령 | `axnavi-ide` (PATH에 추가) |
| 설정·확장 | `%USERPROFILE%\.axnavi-ide`, `%APPDATA%\AX-NAVI IDE` — VS Code와 따로 저장 |

여러 PC 에 한꺼번에 깔 때(관리자):

```powershell
HNIX-AX-PC-Setup-<버전>.exe /VERYSILENT /SERVER=http://<플랫폼>:8700            # 사용자별 설치
HNIX-AX-PC-Setup-<버전>.exe /VERYSILENT /ALLUSERS /SERVER=http://<플랫폼>:8700  # PC 공용(Program Files)
```

`/SERVER` 를 주면 플랫폼 주소까지 넣어 두어, 사용자는 IDE 를 열어 승인만 누른다. 제거는 "앱 및 기능"에서 한다. 예전 판(zip + `설치.cmd`)으로 깐 PC 도 새 설치 파일로 덮어 설치하면 된다.

### 보안 프로그램이 막거나 지울 때

1.2.0 부터 실행 파일과 설치 파일이 모두 코드 서명되어 있다. 그래도 사내 보안 프로그램(백신·EDR·응용 프로그램 통제)이 막으면, 보안 담당자에게 빌드와 함께 나오는 `AX-NAVI-IDE-<버전>-보안검토.md`(설치 위치·실행 프로세스·통신 대상·인증서 지문)와 `-hashes.csv` 를 주고 **게시자(코드 서명 인증서) 기준 예외**를 요청한다. 게시자 기준이면 판이 바뀌어도 다시 등록하지 않는다. 사내에서 직접 만든 인증서로 서명했다면 그 인증서(.cer)를 그룹 정책으로 PC 의 '신뢰할 수 있는 루트 인증 기관'과 '신뢰할 수 있는 게시자'에 먼저 배포해야 한다.

**쓰던 VS Code에 넣기**

```bash
code --install-extension axnavi-<버전>.vsix
```

IDE와 기능이 같다. 회사 표준 VS Code 설정과 확장을 그대로 두고 AX-NAVI만 더할 때 쓴다.

**판정 엔진은 따로 깔지 않는다**

변경 리뷰, 보안 점검, 단계 게이트, 코드 인덱스를 계산하는 판정 엔진과 스킬 26개는 다음 단계에서 로그인하면 플랫폼이 내려 준다. IDE가 엔진을 자기 안에서 돌리고, 스킬이 부르는 Python도 IDE에 들어 있어서 **PC에 Node.js, Python, AX-NAVI CLI가 없어도 된다.** 필요한 것은 IDE와 Git뿐이다.

## 2. 로그인 — 이 기기 승인

1.1부터 설치본은 HNIX AX 플랫폼에서 승인받은 기기에서만 동작한다.

1. 상태 표시줄의 **AX-NAVI 로그인**이나 채팅 위 "로그인이 필요합니다" 안내의 **[로그인]**을 누른다.
2. 열린 브라우저에서 사내 계정으로 로그인하고, IDE 알림의 승인 코드와 같은지 확인한 뒤 **이 기기 승인**.
3. 상태 표시줄이 **👤 내 이름**(계정 항목)으로 바뀌면 끝이다. 스킬과 판정 엔진은 그 자리에서 받아 온다. 변경 리뷰는 옆의 **리뷰** 항목이다.

플랫폼 주소는 보통 배포할 때 PC 공용 정책에 들어 있다. 없으면 설정 `axnavi.platform.url`에 넣는다. 허가(좌석)가 없다는 안내가 나오면 플랫폼 관리자에게 요청한다. 자세한 내용은 [사용 허가](/axnavi/license.md)에 있다.

## 3. AI 모델 연결

채팅 에이전트가 쓸 Claude 연결을 고른다. 셋 중 가진 것 하나면 된다. 플랫폼 로그인(기기 승인)과는 따로다.

| 연결 | 준비 | 프로필 이름 | 과금 |
|---|---|---|---|
| **Claude 구독** (Pro · Max · Team · Enterprise) | 터미널에서 `claude`를 한 번 실행해 로그인 | `Claude 구독` | 본인 구독·좌석 |
| **API 키** | 환경 변수 `ANTHROPIC_API_KEY` | `Anthropic API 키` | 키 주인 |
| **사내 게이트웨이** | 명령 팔레트 → **AX-NAVI: AI 모델 연결 설정** → 가상 키(`hx-…`) 입력 | `사내 게이트웨이` | 조직 (게이트웨이가 계량) |

- IDE를 처음 열면 가진 것을 찾아 프로필을 만들고 하나를 고른다. 순서는 **조직 선호 → 개발자 선호(`AXNAVI_AUTH`) → 구독 로그인 → API 키 → 게이트웨이**다.
- 조직 정책(`%ProgramData%\axnavi\policy.json`, 저장소 `.axnavi/policy.json`)이 허용하지 않는 연결은 만들지 않고, 있던 프로필도 지운다. 설정의 공급자 목록에서도 정책상 못 쓰는 공급자는 흐리게 **정책상 사용 불가**로 보인다. 정책에 없는 연결로 작업을 시작하면 그 자리에서 멈추고 이유를 말한다.
- 구독 로그인이 풀렸으면 "터미널에서 `claude` 를 한 번 실행해 로그인하라"고, 네트워크가 끊겼으면 그렇게 한국어로 알려 준다. 인증 실패(401·403)는 자동으로 되풀이하지 않고 **[로그인]**·**[키 다시 받기]**·**[AI 모델 연결 설정]** 단추를 보여 준다.
- 구독 연결은 개발자 본인이 로그인한 `claude`를 언어 모델로만 부른다. 이때 API 키 환경 변수를 빼므로 의도와 다르게 종량제로 과금되지 않는다.
- 게이트웨이 키는 이 PC의 보안 저장소에만 저장된다.
- PC에서 돌리는 로컬 모델(Ollama, LM Studio 등 `localhost`)은 어느 경로에도 속하지 않아 정책과 관계없이 쓸 수 있다. 설정 화면에서 프로필을 직접 추가한다.

자세한 경로 규칙은 [Claude 연결](/getting-started/connect.md)에 있다.

## 4. 프로젝트 열고 색인

1. **파일 › 폴더 열기**로 저장소를 연다.
2. 명령 팔레트(`Ctrl+Shift+P`)에서 **AX-NAVI: 색인 만들기 (전체)**를 실행한다. AI를 부르지 않고 스크립트로 화면 → 버튼 → 함수 → SQL → 테이블 지도를 만든다. 코드가 바뀌면 **색인 갱신 (변경분)**.
3. 처음 맡는 프로젝트라면 채팅에서 `/harness-init`을 실행한다. 색인에 더해 프로젝트 규칙(`CLAUDE.md`), 코드 패턴, 검증 리포트까지 만든다.

색인은 MCP 도구 `QueryIndex`로 에이전트에 자동으로 붙는다(설정 `axnavi.mcp.autoRegister`). 에이전트는 "이 테이블을 쓰는 화면" 같은 질문에 grep 대신 색인을 조회한다. 색인 조회는 읽기 전용이라 승인 없이 바로 돌고, 채팅에는 조회 대상과 결과만 짧게 보인다(MCP 설정에서 **항상 허용**을 끄면 다시 묻는다). 스킬이 판정 엔진을 직접 부르는 명령(로그인 때 받은 엔진의 스크립트)도 승인 단계와 상관없이 바로 돌고, 채팅에 명령 줄을 남기지 않는다. 엔진 밖 명령이 섞이거나 파일로 돌려쓰는 명령은 원래대로 묻는다.

## 5. 채팅

채팅은 **오른쪽 보조 사이드바**에 있다. 폴더를 열면 기본으로 보이고, 닫았다면 **보기 › 모양 › 보조 사이드바**(`Ctrl+Alt+B`)로 다시 연다. 첫 화면에서는 마스코트 **나침이**가 인사하고, **예시 요청** 버튼(누르면 입력창에 채운다)과 최근 작업이 아래에 나온다. 입력창 아래에서 모드와 연결을 고른다.

| 모드 | 쓰는 때 |
|---|---|
| **🏗️ 설계** | 계획과 설계. 바꾸기 전에 범위와 단계를 정한다 |
| **💻 코드** | 코드를 쓰고 고친다. 파일 수정은 diff로 보여 주고 승인받는다 |
| **❓ 질문** | 읽기만 한다. "이 버튼을 누르면 어디까지 가나?" |
| **🪲 디버그** | 오류 원인을 좁혀 간다 |
| **🪃 작업 분배** | 큰 작업을 하위 작업으로 나눠 여러 모드에 맡긴다 |

- `@`로 파일·폴더·문제 목록을 대화에 붙인다.
- **📎 파일 첨부**(입력창 오른쪽) — 고른 파일이 `@`멘션으로 들어간다. 작업 폴더 밖 파일(내려받은 구현 명세 등)은 `<작업 폴더>/.axnavi/attachments`로 복사되고, `.git/info/exclude`에 들어가 git 상태·변경 리뷰에 섞이지 않는다.
- **끌어다 놓기** — 탐색기에서 파일·이미지를 **Shift를 누른 채로** 입력창에 놓는다(VS Code 웹뷰 특성). 문서는 첨부, 이미지는 이미지로 붙는다. Claude 구독 연결에서도 이미지를 읽는다(1.0.4).
- 파일 수정, 터미널 명령, MCP 도구 호출은 실행 전에 승인을 받는다. 묻지 않고 할 범위는 입력창 아래 **승인 모드** 칸(방패 아이콘과 `매번 확인` · `읽기 자동` · `수정 자동` · `모두 자동` 같은 짧은 이름)에서 하나만 고르면 된다.

  | 승인 모드 | 묻지 않고 하는 일 | 여전히 묻는 일 |
  |---|---|---|
  | **매번 확인** | 코드 색인 조회, AX-NAVI 엔진 명령, 플랫폼 허브의 조회 도구(서비스 요청·문서 조회) | 파일 읽기·수정·명령 실행 등 그 밖의 모든 것 |
  | **읽기까지 자동** | 파일 읽기·검색 | 수정, 명령 |
  | **수정까지 자동** | 작업 폴더 안 파일 읽기·수정, 모드 전환, 하위 작업 | 터미널 명령, MCP 쓰기 도구 |
  | **모두 자동** | 위에 더해 터미널 명령, MCP 도구 | 거부 목록의 명령, 작업 폴더 밖·보호 파일 수정, 사용자에게 하는 질문 |

  **모두 자동**을 고르면 경고가 붙는다 — 플랫폼 허브(`hnix-ax`)의 쓰기 도구까지 묻지 않고 실행하므로 서비스 요청 등록·댓글·문서 저장 같은 변경이 바로 반영될 수 있다. 항목을 하나하나 고르려면 메뉴의 톱니바퀴(설정 › 자동 승인)로 간다. 그렇게 고른 상태는 **사용자 지정**으로 보인다.
- 작업마다 체크포인트가 남아 이전 상태로 되돌릴 수 있다.

## 6. 슬래시 명령 — AX-NAVI 스킬

입력창에서 `/`를 누르면 AX-NAVI 스킬 목록이 나온다. 스킬은 로그인할 때 플랫폼에서 받아 오므로, 플랫폼의 스킬이 갱신되면 다음 로그인 확인 때 함께 바뀐다.

<figure><img src="img/axnavi-ide-slash.png" alt="입력창에 /를 누르면 나오는 슬래시 명령 목록 — 'AX-NAVI 스킬' 머리글 아래 /analyze-impact, /cross-repo-modify, /cross-repo-scaffold, /find"><figcaption><code>/</code>를 누르면 <b>AX-NAVI 스킬</b> 머리글 아래 스킬이 두 줄 설명과 함께 나온다.</figcaption></figure>

| 하고 싶은 일 | 명령 |
|---|---|
| 처음 맡은 코드베이스 파악 | `/harness-init` — 색인, 프로젝트 규칙, 코드 패턴, 검증 리포트 |
| 기능 위치 찾기 | `/find` (`/find-feature`) |
| 흐름·로직 따라가기 | `/flow` (`/trace-logic`) — 진입점부터 DB까지 |
| 바꾸면 어디가 영향받나 | `/impact` (`/analyze-impact`) — 직간접 영향과 위험도 |
| 안전하게 고치기 | `/modify` (`/safe-modify`) — 사전 영향 분석 → 적용 → 사후 안전성 평가 |
| 작은 수정은 빠르게 | `/vibe` — 영향·안전성 게이트는 건너뛰고 패턴과 최소 검증만 |
| 새 기능 뼈대 | `/scaffold` (`/scaffold-feature`) — 프로젝트 컨벤션대로 Controller·Service·DAO·테스트 |
| SQL 리뷰 | `/sql` (`/review-sql`) — 사용처, 인덱스, N+1, 인젝션, 락 |
| 보안 점검 | `/security-scan` |
| 요구사항 명확화 | `/spec-gate` — 시작 전 목적·범위·제약 인터뷰 |
| 산출물 | `/sdlc-docs` |
| 위키 | `/wiki` (`/generate-wiki`), `/publish-wiki`, `/wiki-hub` |
| 마이그레이션 계획 | `/plan-migration` |
| 백엔드·프론트엔드 저장소가 나뉜 경우 | `/pair-init`으로 짝짓고 `/cross-repo-modify`, `/cross-repo-scaffold` |

괄호 안은 같은 스킬의 원래 이름이다. 짧은 이름이 별칭이다.

## 7. 설정

| 설정 | 기본값 | 뜻 |
|---|---|---|
| `axnavi.platform.url` | (비움) | HNIX AX 플랫폼 주소 — 로그인·스킬 배포·서버 엔진. PC 공용 정책에 `platform` 이 있으면 그것이 우선이고 이 설정은 쓰지 않는다. 비우면 환경 변수 `HNIX_AX_SERVER`, 그다음 설치할 때 넣은 주소 |
| `axnavi.cliPath` | (비움) | 쓰던 VS Code에 확장만 깔고 로그인 없이 쓸 때의 CLI 실행 파일. IDE 설치본은 쓰지 않는다 |
| `axnavi.cliRoot` | (비움) | 위와 같은 경우의 CLI 패키지 폴더 |
| `axnavi.offline` | `true` | 폐쇄망 모드 — 시작할 때 공개 모델 목록을 받아 오지 않는다 |
| `axnavi.mcp.autoRegister` | `true` | 색인 도구를 에이전트 MCP 서버로 자동 등록 |
| `axnavi.gateway.baseUrl` | (비움) | 사내 게이트웨이 주소. 조직 정책에 있으면 그것이 우선 |
| `axnavi.gateway.model` | (비움) | 게이트웨이 모델 별칭 |
| `axnavi.insight.server` | (비움) | 사용량 전송 서버(플랫폼 사용량·비용). 명령 **AX-NAVI: Insight 키 설정**의 키와 함께 있을 때만 작업 요약을 보낸다. 플랫폼에 로그인한 IDE 는 넣지 않아도 된다 |

명령 팔레트에서 `AX-NAVI`를 입력하면 모든 명령이 나온다. 환경이 이상하면 **AX-NAVI: 환경 진단**부터 실행한다.

| 자주 쓰는 명령 | 하는 일 |
|---|---|
| **AX-NAVI: 플랫폼 로그인 (이 기기 승인)** | 회사 HNIX AX 플랫폼에 로그인 |
| **AX-NAVI: AI 모델 연결 설정** | 구독·API 키·사내 게이트웨이 중 채팅이 쓸 연결 |
| **AX-NAVI: 키 다시 받기 (사내 모델·MCP 허브)** | 플랫폼에서 이 PC 전용 키를 새로 받는다 |
| **AX-NAVI: 색인 만들기 (전체)** · **색인 갱신 (변경분)** | 코드 색인 |
| **AX-NAVI: 계정·사용 허가 상태** | 로그인한 사람·기기·엔진 위치·토큰 만료 |
| **AX-NAVI: 환경 진단** | 엔진 위치·과금 경로 같은 실행 환경 확인 |
