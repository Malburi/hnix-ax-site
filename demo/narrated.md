# 해설 시연 영상 — 운영 · 데이터와 통제 · AX-NAVI CLI · AX-DataLake

목소리 해설이 붙은 시연 영상 네 편이다. 시연회에서 틀어 두고 설명 없이 보여 줄 수 있게 만들었다. 깨끗하게 새로 띄운 시연 환경(시험 데이터 없음)에서 실제 제품을 조작하며 녹화했다. 판은 AX Platform 0.9.3 · PMS-X 1.3.17 · AX-DataLake 0.6.0 · AX-NAVI IDE 1.2.8 이다(2026-11-15 다시 녹화 — 서비스 요청 분류·배정 한 칸, 흐름의 답변 초안, 레이크 파일 목록, 플랫폼·레이크 화면 글꼴 Pretendard, 서비스 요청 상세는 요청자 개인정보를 가려 승인 없이 읽음). ③ 은 AX-NAVI CLI 1.0.1(엔진 0.1.0-alpha.27)이다.

- 해설은 사내 PC에서 돌린 음성 합성으로 만들었다. 장면마다 해설이 끝날 때까지 화면이 머문다.
- AI 답을 기다리는 구간(창구 답 · 흐름 실행 · 분류 의견 · IDE 에이전트 · 지식 문서 초안)은 빨리 감았다. 답 자체는 사내 로컬 모델이 그 자리에서 낸 것이다.
- 등장 인물과 회사는 시연용으로 만든 것이다(김현업 · 서운영 · 이개발, ○○공사 인사팀).

## ① 운영 — 현업 문의 한 건이 지식이 되기까지 (6분 40초)

<video controls preload="metadata" poster="video/narrated/ops.jpg" src="video/narrated/ops.mp4" style="width:100%;border-radius:10px;background:#0f1d2b"></video>

| 순서 | 화면 | 보여 주는 것 |
|---|---|---|
| 1 | 현업 창구(김현업) | "급여 계산 배치가 늦어진 원인"을 AX-DataLake에 모아 둔 **장애 보고서**를 근거로 답한다. 보고서 속 전화번호는 레이크에 넣을 때 이미 가려졌고, 창구는 레이크를 분석가 권한으로만 읽는다 |
| 2 | 현업 창구 → 담당자에게 넘기기 | "사원 조회에 퇴사자가 같이 나와요"는 운영 매뉴얼로 안내하고, 그래도 안 풀리면 대화 기록과 함께 **PMS-X 서비스 요청**으로 접수된다 |
| 3 | 업무 자동화 · 승인함 | 감시 트리거가 새 요청을 '서비스 요청 분류·처리' 흐름에 넣는다. 사내 모델 분류 → 문의면 지식 문서를 찾아 근거를 단 **답변 초안** → 사람 확인에서 멈추고, 운영 책임자가 승인함에서 답변 초안을 읽고 승인한다(실행한 사람은 스스로 승인 못 함) |
| 4 | PMS-X(서운영) | 분류 의견이 유형·우선순위·대상 화면·담당 후보를 '다음 단계' 칸에 채우고 → 한 번에 **담당 배정** → 처리 시작, 대상 화면을 As-Is 메뉴 트리와 잇고, 구현 명세 내보내기와 As-Is 화면 뷰어 |
| 5 | AX-NAVI IDE(이개발) | 요청 번호만 주고 맡긴다. 조회 도구는 바로, 파일 수정만 개발자 확인 — 요청 본문을 읽고(요청자 이름·연락처는 허브가 가림) 이름 조회 SQL 에 재직 조건 |
| 6 | PMS-X 처리 완료 · 지식 문서 | 처리 내용을 남기고 닫으면 처리 기한 준수율·월간 보고에 들어간다. 끝난 요청으로 지식 문서 초안(증상·원인·조치)을 만들어 등록 |

## ③ AX-NAVI CLI — IDE 밖에서, 같은 엔진으로 (3분 33초)

<video controls preload="metadata" poster="video/narrated/cli.jpg" src="video/narrated/cli.mp4" style="width:100%;border-radius:10px;background:#0f1d2b"></video>

AX-NAVI IDE 는 VS Code 기반이다. 이클립스·인텔리J 를 쓰는 개발자, 서버에 접속해 터미널에서 일하는 사람, 사람 없이 도는 CI 에서는 IDE 를 쓸 수 없다 — 그런 곳에서 같은 엔진과 스킬을 쓰는 것이 CLI 이고, 저장소 전체를 한 번에 다루는 일괄 명령(현대화 레시피·테스트 골격·커버리지)과 머지 게이트도 CLI 가 맡는다.

| 순서 | 화면 | 보여 주는 것 |
|---|---|---|
| 1 | `axnavi login` → 브라우저 | 설치본에는 엔진이 없다. 승인 주소·확인 코드 → 플랫폼에 사내 계정으로 로그인해 **이 기기 승인** → 엔진을 받는다 |
| 2 | `axnavi index build` | AI 없이 인사시스템 47개 파일의 지도(화면·자바·매퍼 SQL·테이블·호출 관계) — 0.9초 |
| 3 | 대화형 모드 `/find` | "사원 목록 조회 기능이 어디 있어?" → 조회 버튼 → JS → 컨트롤러 → 서비스 → 매퍼 SQL → 테이블을 파일·줄 번호로, 작업 중인 `${}` 도 짚고 영향도 분석을 권함 |
| 4 | `/impact` | selectEmpList 의 정렬을 바꾸면 — 목록 조회·엑셀 다운로드 두 곳, 화면, 테스트 없음, 확인하지 못한 것, 위험도 |
| 5 | `axnavi modernize oracle-pg` | IDE 에 없는 일괄 명령 — AI 없이 36개 파일에서 Oracle→PostgreSQL 고칠 곳: 자동 73건 · 수동 1건(MERGE), `--apply` 뒤 `--verify` |
| 6 | `axnavi review` · `$LASTEXITCODE` | 정렬 컬럼을 `${}` 로 붙인 변경 → **STOP**(SQL 인젝션 · OWASP A03 · CWE-89), 종료 코드 4 — CI 러너에서 머지를 막는다 |

> ③ 의 터미널 출력은 실제 명령이 낸 그대로다. 스킬(`/find` · `/impact`)의 에이전트는 개발자 본인 Claude 구독으로 돌렸다 — 회사 설치본의 기본 경로는 사내 게이트웨이이고, 구독은 PC 정책이 허용할 때만 쓴다(시연 PC 의 작은 CPU 모델은 코드 탐색 답이 부정확해 쓰지 않았다). 화면의 비용 표시와 녹화 PC 의 이름·폴더는 가렸다(`DEV-PC01` · `W:\`).

> ② 의 레이크 로그인(SSO 단추)과 사용자 화면의 '사내 계정'은 시연 레이크에 예시 AD·SSO 설정만 넣고 찍은 모습이다(실제 디렉터리 연결 없음). 설정 방법은 [제품 조합과 함께 설치할 때](/getting-started/together.md)와 매뉴얼의 계정 절에 있다.

## ④ AX-DataLake — 회사 데이터를 모으고 권한대로 쓰기 (4분 30초)

<video controls preload="metadata" poster="video/narrated/lake.jpg" src="video/narrated/lake.mp4" style="width:100%;border-radius:10px;background:#0f1d2b"></video>

AX-DataLake 를 ITO 데이터에 한정하지 않고 회사 데이터 기반으로 보여 준다. 고객 업무 DB(가상 ERP)의 주문 100만 건과 Kafka 로 들어오는 실시간 주문을, 레이크 서버 두 대(수집 · 조회)로 띄운 AX-DataLake 0.6.1 에서 녹화했다(2026-11-18).

| 장면 | 화면 | 보여 주는 것 |
|---|---|---|
| 1 | 원본 연결 · 동기화(노드 A) | 업무 DB 에 읽기 전용으로 붙어 주문은 1분마다 바뀐 것만, 상품 마스터는 한 시간마다 통째로 |
| 2 | 실시간 수집(노드 A) | Kafka 토픽의 주문 이벤트(초당 10건)를 들어오는 대로 테이블에 — 누적 행이 올라간다. Debezium 이면 업무 DB 변경(생성 · 수정 · 삭제)을 그대로 |
| 3 | 카탈로그 · 계보 | 100만 건, 열 설명, 가림 표시, 시점 이력 · 업무 DB → 레이크 테이블 → 화면 조회 · AI 질문 |
| 4 | 거버넌스 | 분석가 조회 권한, 이름 · 전화 가림, 소속별 행 제한 |
| 5 | 대시보드(관리자 · 노드 A → 서울 분석가 · 노드 B) | 같은 대시보드가 다른 서버에서도 같은 권한으로 — 서울 주문만, 이름 · 전화는 가림, Kafka 실시간 주문도 서울 것만 |
| 6 | AI 분석(노드 B) | 확인된 질문은 모델 없이 같은 SQL, 결과에도 가림 · 행 제한 |
| 7 | 여러 대 구성 | 카탈로그 PostgreSQL · 공유 저장소 — 수집 서버를 멈춰도 조회는 이어지고, 다시 켜면 밀린 데이터를 따라잡음 |

> ④ 의 레이크 두 대는 PC 한 대 안에서 띄운 노드 둘이고, 공유 저장소는 공유 폴더(NAS 대신)다. 실제 서버 여러 대 · S3 저장소로는 아직 확인하지 않았다. 처음 보는 질문에 사내 모델이 SQL 을 만드는 장면은 시연 PC 의 작은 모델로는 결과가 고르지 않아 넣지 않았다.
