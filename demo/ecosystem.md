# AI 생태계 워크플로우

HNIX AX 전체를 네 장의 그림으로 본다. 원본은 draw.io 파일 하나(4쪽)이고, [내려받아](download/hnix-ax-ecosystem.drawio ':ignore') diagrams.net에서 열어 고칠 수 있다. 그림을 누르면 크게 보인다.

| 쪽 | 무엇을 보나 |
|---|---|
| 1 | 한눈에 — 사람 여섯 역할 · 제품 넷 · 고객 시스템 · 모델이 어떻게 이어지나 |
| 2 | 운영 워크플로우 — 새벽 경보 하나가 장애·진단·수정·지식이 되기까지(통합 점검 번호와 같다) |
| 3 | 개발·전환 워크플로우 — 낯선 레거시를 넘겨받아 안전하게 고치기까지 |
| 4 | AI 거버넌스 — 무엇이 AI를 쓰든 지나는 통제 지점 넷 |

| 사람 | 주로 쓰는 곳 |
|---|---|
| 현업·고객 | 현업 창구(매뉴얼·KB 근거 답변), 고객 포털 |
| 운영자(L1·L2) | PMS-X SM(장애·SR·SLA), 플랫폼 런북·승인함 |
| 개발자 | AX-NAVI IDE, 머지 요청의 CI 게이트 |

| 데이터 분석가 | AX-DataLake(객체 탐색·SQL·AI 질문·계보) |
| 관리자·보안 | 게이트웨이·허브 정책, 키, 감사, 전사 AI 관측 |

## 2. 운영 워크플로우

<figure><img src="img/ecosystem-p2.png" alt="운영 워크플로우 — 고객·현업, AX Platform, 모델, AX-DataLake, PMS-X, AX-NAVI 레인에 걸친 ①~⑳ 단계"><figcaption>새벽 2시 결제 DB 응답 지연 경보에서 시작한다. 번호는 통합 점검(E2E) 단계와 같다.</figcaption></figure>

1. **⑩ 트리거** — 모니터링 경보 웹훅이 경보 진단 에이전트를 사람 없이 깨운다. 같은 경보가 다시 오면 건너뛴다.
2. **① 경보 접수** — PMS-X가 장애·SR을 만든다. 같은 경보는 하나로 묶는다.
3. **⑳ 온톨로지** — 에이전트가 허브의 `datalake__*` 도구로 장애 → 같은 구성 요소의 **직전 72시간 변경**을 SQL 없이 따라간다. 에이전트도 키 주인과 같은 가림·행 제한을 받는다.
4. **④⑫ 승인** — 진단 요청·조치(런북)는 승인 대기. 요청자가 아닌 사람이 승인해야 한 번 실행된다.
5. **⑪ 현업 창구** — 같은 시각 현업의 "결제가 느려요"에 매뉴얼·KB로 답하고, 장애와 같은 건이면 SR에 잇는다.
6. **② 분류·배정** — 사내 모델이 유형·우선순위·담당자를 추천하고 사람이 확정한다. 모델은 게이트웨이 뒤에 있다.
7. **⑤⑥ 화면 분석·명세** — 버튼 → SQL → 테이블 영향을 보고 구현 명세로 넘긴다.
8. **⑦ 수정·리뷰** — AX-NAVI가 색인 근거로 영향을 찾고, 리뷰 STOP → 수정 → GO. 같은 판정이 머지 요청의 CI 게이트에서 돈다.
9. **⑬ 생산성** — 커밋이 SR에 이어지고 AI 관여가 표시된다.
10. **⑧ KB** — SR을 닫으면 증상·원인·조치·재발 방지 초안을 만들고 사람이 확정한다.
11. **⑲ 운영 데이터** — 장애·변경·SR이 레이크에 쌓여 AI 질문·계열사별 추세로, 계보로 영향 범위를 본다.
12. **⑨⑮ Insight** — 모든 실행·승인·AI 사용이 주체별로 모이고 월간 보고·전사 AI 관측이 된다.

## 3. 개발·전환 워크플로우

<figure><img src="img/ecosystem-p3.png" alt="개발·전환 워크플로우 — PMS-X 수집·As-Is 분석·인수인계, AX-NAVI 색인·SDLC·수정·리뷰, AX-DataLake 레거시 데이터·계보, AX Platform 공통 기반·생산성"><figcaption>SI → SM 인수인계와 레거시 현대화의 흐름. 분석은 AI 없이 전수로, 판단은 근거와 함께, 변경은 게이트를 지나서.</figcaption></figure>

| 단계 | 제품 | 내용 |
|---|---|---|
| 1 수집 · 2 As-Is 분석 | PMS-X | 고객망 PC의 수집기가 소스·DB 메타·화면을 모아, 화면 → 버튼 → 함수 → SQL → 테이블 그래프를 만든다 |
| 3 인수인계 | PMS-X | 갭 리포트·준비도·질문 목록, 화면·데이터·SR 이력·업무 절차·SLA 퀴즈 |
| 4 전수 색인 | AX-NAVI | 호출 그래프·SQL 사용처·트랜잭션·데드 코드 — 분석에 모델 호출 0회 |
| 5 SDLC 산출물 | AX-NAVI | 요구 → 설계 → 개발 → 테스트 단계 게이트 |
| 6 수정·현대화 | AX-NAVI | Java 21·jakarta, Oracle → PostgreSQL 자동 변환 레시피 |
| 7 리뷰·테스트 | AX-NAVI | GO/HOLD/STOP · OWASP · 테스트 생성 · 바뀐 줄 커버리지 |
| 8 산출물 현행화 | PMS-X | 구현 명세·프로그램 대장·위키·추적성을 코드에서 다시 |
| 레거시 데이터 · 계보 | AX-DataLake | 원본 DB를 읽기 전용으로 동기화, 스키마가 바뀌면 파생 테이블·객체·소비 경로까지 영향 범위 |

## 4. AI 거버넌스

<figure><img src="img/ecosystem-p4.png" alt="AI 거버넌스 — 현업·운영자, 개발자, 플랫폼 에이전트, PMS-X AI 보조, 외부 에이전트가 지나는 통제 지점 넷: 모델 게이트웨이, 도구 MCP 허브, 데이터 레이크 거버넌스, 사용 Insight·감사"><figcaption>무엇이 AI를 쓰든 지나는 문은 넷이다.</figcaption></figure>

| 통제 지점 | 지키는 것 |
|---|---|
| ① 모델 — LLM 게이트웨이 | 가상 키·한도·예산, 한국형 개인정보 가명화, 기밀 등급은 사내 모델로만, 요청·응답 본문은 저장하지 않음 |
| ② 도구 — MCP 허브 | 정책(허용·거부·승인 후), 인자 점검, 스키마 drift 차단, 승인함(같은 인자 1회, 본인 승인 불가), 호출 감사 |
| ③ 데이터 — 레이크 거버넌스 | SQL 구조 검사, 테이블 권한, 개인정보 형식별 가림, 소속 행 제한, 액션 승인, 누가 어느 길로 읽었는지 |
| ④ 사용 — Insight·감사 | 호출 주체별 토큰·비용, 정책 위반, 전사 AI 관측(대장에 없는 AI), 감사 로그·월간 보고 |
