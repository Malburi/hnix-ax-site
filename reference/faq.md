# 자주 묻는 질문

### VS Code에서 상용 AI 코딩 에이전트처럼 쓸 수 있나요?

그렇게 쓰는 것이 AX-NAVI IDE다. VS Code 계열 IDE를 설치하면 채팅 에이전트(Architect · Code · Ask · Debug · Orchestrator), 슬래시 명령, 변경 리뷰와 Findings, 보안 점검, 단계 게이트가 들어 있다. 쓰던 VS Code에 `.vsix`만 깔아도 된다. 흔한 기능과의 대응은 [AX-NAVI IDE 개요](/axnavi/README.md)에 있다.

### Claude 구독(Pro·Max)만 있어도 쓸 수 있나요?

AX-NAVI는 된다. 본인 PC에서 `claude`에 로그인해 두면 AX-NAVI가 그 Claude Code에 작업을 맡긴다. Team·Enterprise 좌석도 똑같다. 다만 여러 사람을 대신해 호출하는 서버 기능(게이트웨이, PMS-X AI, 공통 에이전트)은 구독으로 쓸 수 없고 조직 API 키나 사내 로컬 모델을 쓴다. [Claude 연결](/getting-started/connect.md)을 본다.

### 구독과 API 키를 둘 다 갖고 있으면 어느 쪽으로 과금되나요?

AX-NAVI IDE는 **구독 로그인**을 먼저 고르고, 구독 연결에서는 API 키 환경 변수를 빼서 구독으로 과금되게 한다. 채팅 입력창 아래 연결 이름으로 확인하고, 바꾸려면 명령 팔레트 › **AX-NAVI: AI 연결 설정**.

AX-NAVI CLI는 기본이 API 키다. `AXNAVI_AUTH=subscription`을 넣으면 구독을 먼저 쓰고, 이때 위임 프로세스에서 API 키를 뺀다. `axnavi doctor`의 **과금** 줄로 확인한다.

### Claude 없이 사내 모델만으로 쓸 수 있나요?

된다. 게이트웨이에 사내 로컬 프로바이더(vLLM, Ollama 등 OpenAI 호환)를 등록하고 별칭을 만든다. PMS-X AI와 AX-NAVI의 게이트웨이 경로가 그 별칭을 쓴다. 단일 호출 기능(SR 분류, KB 초안, 설명 초안)은 작은 모델로도 동작하지만, 도구를 여러 개 쓰는 에이전트는 7B 이상을 권장한다.

### AI를 끄면 무엇이 남나요?

대부분이 남는다. As-Is 수집·뷰어·영향도, 구현 명세, 인수인계 갭 리포트, AX-NAVI의 색인·변경 리뷰·보안 점검·단계 게이트는 모두 AI 없이 동작한다. AI는 그 위에서 설명·분류·요약을 돕는다.

### AI가 틀리면요?

AI 결과는 모두 초안이다. SR 분류는 후보 목록 안에서만 고르고 사람이 반영해야 저장된다. 설명 초안에는 근거 등급(녹·황·적)이 붙고, 확정해야 산출물에 쓰인다. KB 초안에는 출처 SR이 남는다.

### 같은 사용량이 두 번 세어지지 않나요?

같은 호출은 한 번만 센다. Claude Code는 요청 ID로 텔레메트리와 세션 기록을 묶고, AX-NAVI는 구독·게이트웨이 경로에서 토큰을 따로 보내지 않는다.

### 고객사 폐쇄망에 설치할 수 있나요?

그렇게 만들었다. AX Platform은 Node 런타임을 포함한 zip·tar.gz로, PMS-X는 내장 JRE를 포함한 오프라인 패키지로 설치한다. 둘 다 설치·실행 중 인터넷을 쓰지 않는다.

### 기존 PMS-X나 AX-NAVI를 고쳐야 연결되나요?

아니다. 플랫폼은 커넥터로 읽기만 한다. PMS-X는 운영 역할을 가진 서비스 계정 하나, AX-NAVI는 설치 폴더와 색인된 저장소 경로만 있으면 된다.

### 다른 회사의 에이전트 플랫폼과도 연결되나요?

A2A(Agent2Agent) 프로토콜을 지원하는 에이전트는 MCP 허브에 외부 에이전트로 등록해 도구처럼 쓴다. 반대로 HNIX AX의 도구는 MCP로 열려 있어 MCP를 지원하는 클라이언트가 붙을 수 있다.

### 고객사에 설치한 뒤 연동이 제대로 붙었는지 어떻게 확인하나요?

**관리 › 현장 연결 점검** 화면 하나로 본다. 기본은 이미 남은 기록(마지막 동기화, 웹훅 수신, 최근 모델 요청)만 읽고, 관리자가 "연결 시험 포함 점검"을 누르면 ITSM·MCP 서버·외부 AI 관리 API 에 실제로 붙어 본다. 순서와 고객 쪽 준비물은 [고객사 설치와 연결 점검](/getting-started/onsite.md)에 있다.

### 런북이 중간에 실패하면 어떻게 되나요?

실패·시간 초과로 기록되고, 런북에 원복 런북(`spec.rollback`)을 연결해 두었으면 같은 승인으로 바로 원복이 돈다. 원복 실행은 원래 실행 번호와 함께 남는다. [런북](/platform/runbooks.md#실패하면-원복)을 본다.

### Oracle → PostgreSQL 전환에서 AI 는 무엇을 하나요?

기계적으로 같은 뜻인 치환(NVL, SYSDATE, 한 줄 DECODE 등)은 규칙이 AI 없이 고친다. 페이징 ROWNUM, (+) 조인, CONNECT BY, MERGE 처럼 판단이 필요한 문장만 `--draft` 로 AI 초안과 확인할 점을 받고, 소스에는 사람이 검토해 옮긴다. [현대화 레시피](/axnavi/cli.md#현대화-레시피)를 본다.
