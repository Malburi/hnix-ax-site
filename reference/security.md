# 데이터·보안 원칙

HNIX AX는 고객사 폐쇄망에 들어가는 것을 전제로 만들었다. 아래 원칙은 네 제품에 공통이다.

## 저장하지 않는 것

| 대상 | 원칙 |
|---|---|
| 모델 요청·응답 본문 | 게이트웨이는 저장하지 않는다. 요청 로그에는 시각·키·모델·토큰·비용·결과·개인정보 탐지 건수만 |
| 도구 호출 인자 | MCP 허브 호출 기록에는 인자 이름과 크기만. 승인 대기 중인 인자 원문은 결정하면 지운다 |
| 에이전트 대화 | 실행의 입력과 최종 출력, 단계 메타데이터만. 중간 대화는 승인 대기 중에만 보관 |
| Claude Code 프롬프트·응답 | 텔레메트리로 오지 않는다(Claude Code가 기본으로 가림). 와도 저장하지 않는다 |
| Claude 구독 자격 증명 | 서버로 오지 않는다. 각자 PC에만 있다 |

## 키와 비밀

- 프로바이더 API 키, LDAP 서비스 계정 비밀번호는 AES-256-GCM 암호화 저장소에만 둔다. 암호화 키(`master.key`)는 백업에 함께 담긴다.
- 가상 키(`hx-…`)는 발급할 때 한 번만 보이고, 서버에는 해시만 남는다.
- 설정 파일에는 비밀을 쓰지 않고 `${env:이름}`으로 받는다.

## 데이터 등급과 모델

| 등급 | 갈 수 있는 모델 |
|---|---|
| `public` · `internal` | 별칭에 등록된 대상(Claude 포함) |
| `confidential` | 라우트 규칙에 따라 |
| `restricted` | 사내 로컬 프로바이더만 |

등급은 키·워크스페이스 기본값보다 **올릴 수만** 있다. 기밀 저장소는 AX-NAVI 정책 파일로 사내 게이트웨이만 쓰게 묶는다.

## 개인정보 보호

게이트웨이는 주민등록번호, 전화번호, 이메일, 카드번호, 사업자번호와 직접 정한 패턴을 찾아 가명화·마스킹·차단한다. 가명화한 값은 응답에서 되돌린다. 탐지 건수만 기록하고 값은 남기지 않는다.

## 외부 호출

- PMS-X의 AI 기능은 기본으로 꺼져 있다. 끈 상태에서는 외부 호출이 0건이다. 켜도 사내 게이트웨이로만 간다.
- AX Platform 설치 패키지는 Node 런타임과 확장을 모두 포함한다. 설치·실행 중 인터넷을 쓰지 않는다.
- PMS-X 웹은 글꼴과 라이브러리를 로컬에 번들한다(외부 CDN 0건).
- AX-NAVI의 변경 리뷰·보안 점검·단계 게이트는 모델을 부르지 않아 폐쇄망 CI에서 그대로 돈다.

## 기존 시스템 접근

- AX Platform은 PMS-X를 서비스 계정으로 **조회만** 한다. PMS-X에 새 API 키 인증을 만들지 않았다.
- PMS-X 수집기는 테스트계 화면을 캡처할 때 서버로 가는 변경 요청을 차단한다. DB는 메타데이터만 읽는다.
- 모니터링 경보도 일반 계정(운영 역할)으로 받는다.

## 계정과 감사

- 로컬 계정과 LDAP·AD. 5회 실패하면 잠기고, 실패 사유는 구분해 알려 주지 않는다.
- 로그인, 키 발급·폐기, 정책·프로바이더 변경, 승인 결정, 에이전트 실행은 감사 로그에 남는다.
- Insight의 사용자별 조회는 관리자와 감사자만 한다. 일반 사용자는 본인 기록과 팀 단위 집계만 본다.

## 데이터 레이크(AX-DataLake)

- 원본 DB 에는 **읽기 전용 계정**으로 붙는다. 연결 비밀번호는 마스터 키로 암호화해 두고, 붙지 못했을 때의 오류 문구에서도 지운다.
- 개인정보 열은 형식별로 가리고(주민번호·전화·이메일·카드·계좌·이름·주소), 보는 사람의 소속으로 행을 제한한다. 화면·API 키·MCP 에이전트·AI 질문이 같은 SQL 검사를 지난다.
- 분석가 조회 엔진은 읽기 전용으로 붙고 서버 파일 접근·설정 변경이 잠겨 있다 — SQL 검사를 빠져나가도 쓰기·파일 읽기가 되지 않는다.
- AI 질문은 테이블 구조·설명만 모델에 보내고(값은 보내지 않음), 기밀 등급이 섞이면 사내 모델만 쓴다.
- 누가 어떤 SQL 을 어느 길로 실행했는지(성공·거부·오류) 조회 이력에, 정책·수집·스트림 변경은 감사 기록에 남는다.
