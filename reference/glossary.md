# 용어집

| 용어 | 뜻 |
|---|---|
| **As-Is 분석** | 현재 운영 중인 레거시 시스템을 화면 단위로 분석하는 일. PMS-X의 수집기와 뷰어가 맡는다 |
| **워크플로우** | 버튼 하나가 이벤트 → 함수 → API → 서비스 → SQL → 테이블로 이어지는 흐름 |
| **신뢰도** | 워크플로우 연결선의 확실성. 동적 관측 100%, 정적 분석은 그보다 낮고, 분석자가 확정하면 수동 |
| **원본 숨김** | 레거시 소스가 처음부터 화면에 표시하지 않는 컨트롤·그리드 열(`visible="false"`, `display:none` 등). 캡처에는 없지만 이벤트·흐름은 분석된다. 분석자가 뷰어에서 숨긴 요소와는 별개 |
| **단계 추적** | 이벤트 하나의 경로를 단계 카드로 따라가는 뷰어 기능. 상세도는 업무 · 로직 · 기술 |
| **공정준수율** | 기준일까지의 계획 진척 대비 실적 진척 비율. 100% 이상 양호, 95% 이상 보통, 그 미만 미흡 |
| **근거 등급** | AI 설명 초안이 기대는 흐름의 품질. 녹(충분)·황(일부)·적(부족) |
| **AX-NAVI IDE** | VS Code 계열(VSCodium) IDE에 AX-NAVI 에이전트를 넣은 개발 도구. 같은 확장을 VS Code에 깔아 쓸 수도 있다 |
| **Findings** | 변경 리뷰·보안 점검의 지적 사항 목록. IDE 아래쪽 패널과 문제 탭에 함께 나오고, 항목마다 AI로 고치기를 실행할 수 있다 |
| **색인(인덱스)** | AX-NAVI가 스크립트로 만든 코드 지도. 심볼, 호출 그래프, SQL, 트랜잭션, 엔드포인트, 화면 이벤트 |
| **GO / HOLD / STOP** | 변경 리뷰·단계 게이트의 판정. 종료 코드 0 / 3 / 4 |
| **단계 게이트** | 요구 → 설계 → 개발 → 테스트 단계를 넘어가도 되는지 산출물로 판정하는 것 |
| **ADR** | 아키텍처 결정 기록(Architecture Decision Record). `docs/adr/` |
| **LLM 게이트웨이** | 모든 모델 호출이 지나는 플랫폼 관문. 키·개인정보·예산·등급·계량 |
| **가상 키** | 게이트웨이가 발급하는 `hx-…` 키. 권한 `llm`·`ingest`·`ingest_org`·`mcp` |
| **모델 별칭** | 도구가 부르는 이름(`hnix-local`, `hnix-claude`). 뒤의 실제 모델과 폴백 순서는 관리자가 정한다 |
| **데이터 등급** | `public`·`internal`·`confidential`·`restricted`. `restricted`는 사내 로컬 모델만 |
| **MCP** | Model Context Protocol. AI 클라이언트가 도구를 부르는 표준. 플랫폼의 `/mcp` |
| **MCP 허브** | 사내 도구를 모으고 정책·승인·감사를 거는 플랫폼 모듈 |
| **승인함** | 정책 `approve`에 걸린 도구 호출을 사람이 결정하는 곳 |
| **A2A** | Agent2Agent. 다른 에이전트를 부르는 표준. 허브에 외부 에이전트로 등록한다 |
| **Insight** | AI 사용량과 비용을 모아 보는 플랫폼 모듈 |
| **텔레메트리(OTLP)** | Claude Code가 OpenTelemetry로 내보내는 사용량 기록. 플랫폼 `/v1/logs`가 받는다 |
| **구독 로그인 / API 키 / 사내 게이트웨이** | AX-NAVI가 Claude를 부르는 세 경로 |
| **조직 정책** | AX-NAVI가 쓸 수 있는 경로를 관리자가 정하는 `policy.json` |
| **구현 명세** | SR·CR을 요구사항·흐름·영향·소스·작업·테스트로 묶은 코딩 에이전트 입력 |
| **인수인계 갭 리포트** | SI → SM 이관 전에 비어 있는 분석·메모·산출물·결함을 점수와 질문으로 보여 주는 리포트 |
| **SR / CR** | 서비스 요청(Service Request) / 변경 요청(Change Request) |
| **SLA** | 서비스 수준 협약. PMS-X는 업무시간·공휴일을 반영해 응답·해결 기한을 계산한다 |
| **런북** | 배치 재실행·캐시 비우기처럼 미리 정한 조치. 다른 사람이 승인해야 실행되고, 실패하면 연결한 원복 런북이 같은 승인으로 돈다 |
| **점검(dry-run)** | 런북을 실제로 바꾸지 않고 확인만 하는 실행. 승인 없이 돈다 |
| **현장 연결 점검** | 고객사 설치 뒤 기본 설치·모델·도구 서버·ITSM·Git·외부 AI·자동화 연결 상태를 한 화면에서 보는 기능 |
| **조직 설정(묶음)** | 플랫폼이 AX-NAVI 에 배포하는 규칙·스킬·SDLC 양식·MCP·정책·사용자 정의 모드 묶음. 버전으로 관리한다 |
| **사용자 정의 모드** | IDE 채팅의 역할·허용 도구를 정한 모드(예: SR 처리). 조직 설정으로 배포할 수 있다 |
| **현대화 레시피** | Java·Spring Boot·jakarta·Oracle → PostgreSQL 전환 규칙 묶음. 자동(기계적 치환)과 수동(안내)으로 나눈다 |
| **AI 초안** | 현대화 레시피가 자동으로 못 바꾼 SQL 문장에 대해 AI 가 쓴 변환안. 소스에는 사람이 검토해 옮긴다 |
| **업무 템플릿** | SR·장애·변경을 처리하는 절차 체크리스트. 항목을 완료하면 처리자와 시각이 남는다 |
| **인수인계 이해도 퀴즈** | As-Is 분석·SR 이력·업무 절차·SLA 로 AI 없이 출제하는 인수자 확인 시험 |
| **생산성 보고서** | 커밋·MR 을 SR 과 이어 AI 관여와 공수·리드타임 절감률을 계산하는 보고서 |
