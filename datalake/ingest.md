# 수집 — 파일 · 원본 연결 · 실시간

표 데이터를 레이크에 넣는 길은 셋이다(문서 같은 비정형 자료는 [문서(비정형)](/datalake/documents.md)). 모두 데이터 엔지니어(또는 관리자)가 화면에서 정하고, 결과는 카탈로그에 테이블로 보인다.

| 길 | 언제 | 방식 |
|---|---|---|
| [파일](#파일) | 엑셀·CSV 로 받은 자료, 한 번 넣고 끝 | 올리기 → 미리 보기(엑셀은 시트·머리글 줄 고르기) → 새로 만들기·통째로 바꾸기·뒤에 붙이기 |
| [원본 DB](#원본-db) | 업무 DB 의 테이블을 정기적으로 | 통째로·증분(워터마크)·병합(키), 분 단위 주기 |
| [실시간](#실시간-스트림) | 로그·경보·이벤트, DB 변경 이력 | Kafka 토픽·HTTP 이벤트 → 묶음으로 쌓기 |

## 파일

<figure><img src="img/datalake-ingest.png" alt="파일 수집 화면 — 1. 파일 올리기 끌어다 놓기 칸(CSV·TSV·Excel·Parquet·JSON·NDJSON, EUC-KR 자동 변환)과 수집 기록 표"><figcaption>파일 수집. 올리면 열 이름·타입을 추정해 앞 20행을 보여 주고, 확인하면 레이크 테이블로 넣는다.</figcaption></figure>

- 형식: CSV · TSV · 엑셀(XLSX · XLS) · Parquet · JSON · NDJSON. 한 파일 1GB 까지.
- **EUC-KR(CP949) CSV** 는 자동으로 알아보고 UTF-8 로 바꿔 읽는다(국내 업무 시스템에서 내려받은 파일 대부분).
- 방식: 새로 만들기(같은 이름이 있으면 거절) · 통째로 바꾸기 · 뒤에 붙이기(열 이름으로 맞춤).
- 기록: 수집 기록에 파일·대상·행 수·결과가 남고 감사 기록에도 남는다.

### 엑셀

사람이 보기 좋게 꾸민 **보고서형 엑셀**도 그대로 올린다. 외부 프로그램 없이 XLSX 와 예전 형식 XLS(Excel 97~2003)를 읽는다.

| 원본 시트에 있는 것 | 레이크 테이블에서 |
|---|---|
| 맨 위 제목·작성일 줄 | 건너뛰고 **머리글 줄을 자동으로** 찾는다(번호로 정할 수도 있다) |
| 가로로 합친 묶음 제목 아래 두 줄 머리글(`요청 처리 건수` / `7월·8월·9월`) | `요청 처리 건수_7월` 처럼 이어 붙인 열 이름 |
| 세로로 합친 셀(`경영지원` 이 세 행에 걸침) | 행마다 값을 채운다 |
| 합계·소계·총계 행 | 기본으로 뺀다 — 분석 때 두 번 더해지지 않게 |
| 날짜 서식 숫자 · 백분율 · 참거짓 | DATE·TIMESTAMP · 숫자(0.91) · BOOLEAN 열. 글자로 저장된 `00123` 같은 번호는 글자 그대로 |

- **시트 고르기**: 한 시트 · 모든 시트를 한 테이블로(시트 이름 열 `_sheet`) · 시트마다 테이블(`테이블_시트이름`, 한 번에 모두 성공하거나 모두 실패). 숨긴 시트는 표시하고 고를 때만 넣는다.
- 읽기 방식을 바꾸면 바로 다시 펴서 미리 보기를 보여 준다.
- 암호 걸린 파일·Excel 95 이전 형식·확장자만 `.xls` 인 HTML 파일은 이유를 알린다.
- 같은 엑셀을 [문서 묶음](/datalake/documents.md)에 넣으면 테이블 대신 **찾기용 조각**(시트마다 표)이 된다.

## 원본 연결

<figure><img src="img/datalake-sources.png" alt="원본 연결 화면(데이터 엔지니어) — ERP 계약(시연) SQLite 파일 연결과 연결 시험, 동기화 erp-contracts(main.contracts → erp.contracts, 병합(키로 바꿈), 기준 updated_at, 60분)와 지금 실행·고치기"><figcaption>원본 연결. 연결을 시험하면 원본 테이블(REST 는 자원, 폴더는 파일 패턴) 목록이 나오고, 누르면 그 동기화를 만든다.</figcaption></figure>

| 원본 | 붙는 방법 |
|---|---|
| PostgreSQL · MySQL/MariaDB · SQLite | SQL 엔진이 원본에 **읽기 전용**으로 붙어 바로 옮긴다 |
| Oracle | 순수 JS 드라이버 — **오라클 클라이언트 설치가 필요 없다.** 열 타입을 오라클 정보로 정한다(NUMBER(p,s) → 소수 정밀도 그대로, DATE → 시간대 밀림 없이). 원본 SQL(오라클 문법)로도 가져온다 |
| SQL Server | 순수 JS 드라이버(ODBC 설치 불필요). decimal·money → 소수 정밀도 그대로, datetime2 → 저장된 시각 그대로. 원본 SQL 도 된다 |
| Snowflake | **SQL API(HTTPS)** 와 프로그램 접근 토큰 — 드라이버가 없다. 오래 걸리는 문장은 끝날 때까지 기다리고, 결과 묶음을 끝까지 받는다. 고객이 이미 Snowflake 를 쓰면 경쟁하지 않고 원본으로 붙여 필요한 테이블만 고객망 레이크로 |
| REST API | JSON 목록 API. 연결에 자원(이름=경로)을 정하고, 쪽 넘김(쪽 번호·건너뛰기·커서·다음 주소)을 끝까지. 증분은 지난 워터마크를 질의 값(예: `updatedSince`)으로. Jira·ServiceNow 는 미리 채우기 단추가 있다 |
| 공유 폴더 · S3 호환 | 배치가 떨궈 두는 CSV·Parquet·JSON·**엑셀**을 패턴(예: `daily/*.csv`, `monthly/*.xlsx`)으로 한 테이블에. 파일마다 열이 조금 달라도 이름으로 맞추고, `filename` 열 워터마크로 **새 파일만** 가져온다. 엑셀은 파일마다 [보고서형 시트를 펴서](#엑셀) 넣고(시트·머리글 줄·합계 행 빼기는 연결에서 정함), 엑셀이 열어 둔 잠금 파일(`~$…`)은 뺀다. 연결 폴더 밖은 고를 수 없다 |

| 방식 | 하는 일 | 맞는 테이블 |
|---|---|---|
| 통째로 | 매번 새로 만든다 | 코드·기준 테이블 |
| 증분 | 워터마크 열(갱신 시각·순번)이 지난번보다 큰 행만 붙인다 | 로그·이력 |
| 병합 | 새로 바뀐 행을 키로 바꿔 넣는다 | 주문·고객처럼 고쳐지는 테이블 |

- 테이블 변경과 새 워터마크는 **한 번에 성공하거나 한 번에 실패**한다 — 중간에 끊겨도 다음 실행이 같은 자리부터 다시 한다.
- 원본에 새 열이 생기면 레이크 테이블에도 열을 늘린다.
- 연결은 **관리자만** 만들고, 비밀번호는 마스터 키로 암호화해 둔다. 붙지 못했을 때의 오류 문구에서도 비밀번호는 지운다.
- 주기 실행은 서버가 맡는다(여러 대로 띄워도 한 동기화는 한 번만 돈다).

> Oracle·SQL Server 는 타입 변환·SQL 조립까지, Snowflake 는 흉내 서버로 비동기 실행·결과 묶음까지 자동 시험했다. 실제 서버 연결은 현장(PoC)에서 확인한다. 읽기 전용 계정(`SELECT` 권한만)·읽기 전용 역할의 토큰을 쓴다.

동기화가 무엇을 어디로 옮겼는지는 [계보](/datalake/lineage.md)에 그대로 나온다.

## 실시간 스트림

<figure><img src="img/datalake-streams.png" alt="실시간 수집 화면 — Kafka 변경 반영(CDC) 스트림 erp-orders-cdc 와 붙이기 스트림 monitoring-alerts, 상태 '오류'와 원인(Kafka 브로커에 연결하지 못함), 누적 행·마지막 쓰기, 분당 행·대기 행, 밀린 메시지(건) '세어 보기', 줄 끝 다시 시작·멈추기·삭제"><figcaption>실시간 수집. 누적 행·분당 행·대기 행·밀린 메시지(Kafka)·마지막 쓰기를 5초마다 갱신한다. 시연 환경은 Kafka 를 꺼 두어 두 스트림이 '오류'로 보인다.</figcaption></figure>

| 받는 곳 | 형식 | 쌓는 방식 |
|---|---|---|
| Kafka 토픽(TLS·SASL 로그인 가능) | JSON | **붙이기** — 받은 그대로(로그·이벤트). 수신 시각·파티션·오프셋 열을 붙인다 |
| HTTP(`POST /api/v1/streams/<id>/events`, 수집 범위 API 키) | JSON 객체·배열·NDJSON | **키로 바꾸기** — 같은 키는 최신 값만(상태 테이블) |
|  | Debezium 변경 이벤트 | **변경 반영(CDC)** — 생성·수정·삭제를 그대로(원본 DB 의 복제본) |

- **정확히 한 번.** 묶음마다 테이블 변경과 Kafka 의 읽은 위치를 같은 트랜잭션에 쓴다. 서버를 멈췄다 켜도 메시지가 빠지거나 두 번 들어가지 않는다(실제 Kafka 로 멈춤·재시작 시험).
- 묶음 크기(행·시간)를 정한다. 작게 자주 쓰면 파일이 잘게 쪼개지므로, 매일 [파일 정리](/datalake/operations.md#파일-정리)가 합친다.
- 새 필드가 오면 열을 늘리고, 중첩 객체는 JSON 글자 열로 둔다(`json_extract_string` 으로 꺼낸다).
- JSON 이 아니거나 형식이 다른 메시지는 건너뛰고 수를 센다 — 스트림을 멈추지 않는다.
- 쓰기에 실패하면 묶음을 버리지 않고 되돌려 두고 상태를 '오류'로 바꾼다. 원인을 고치고 다시 시작하면 그 자리부터 읽는다.

HTTP 로 보내기:

```bash
curl -X POST http://lake.corp.local:8790/api/v1/streams/<스트림 ID>/events?wait=1 \
  -H "X-API-Key: axdl_…(수집 범위 키)" -H "Content-Type: application/json" \
  -d '[{"host":"was01","level":"ERROR","msg":"연결 끊김"}]'
```
