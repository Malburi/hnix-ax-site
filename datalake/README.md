# AX-DataLake

AX-DataLake는 고객사 폐쇄망에서 도는 **레이크하우스**다. 흩어진 업무 DB·파일·이벤트를 표준 파일 형식으로 한곳에 모으고, 사람(SQL·BI)과 AI 에이전트가 **같은 권한·가림 규칙**으로 읽게 한다. 서버 하나로 시작해 저장소와 계산 노드를 나눠 늘릴 수 있다. 테이블 위에는 장애·서비스·변경·담당자 같은 **업무 객체(온톨로지)**를 얹어 SQL 없이 따라가고, **계보**로 데이터가 어디서 와서 어디로 가는지 본다.

## 왜 필요한가

| 기존 방식 | AX-DataLake |
|---|---|
| 시스템마다 DB 가 따로 있고, 분석할 때마다 담당자에게 추출을 부탁한다 | 원본 DB 를 **읽기 전용**으로 붙여 정해진 주기로 가져온다(통째로·증분·키 병합) |
| 로그·경보·장애 이벤트는 쌓이지 않고 흘러간다 | Kafka 토픽·HTTP 이벤트를 **실시간**으로 받아 테이블에 쌓는다. 멈췄다 다시 켜도 빠지거나 겹치지 않는다 |
| 개인정보가 든 테이블은 통째로 막거나 통째로 연다 | **열 가림**(주민번호·전화·이메일·카드·계좌·이름·주소 형식별)과 **행 제한**(소속별)으로 필요한 만큼만 연다 |
| AI 에 데이터를 맡기면 무엇을 봤는지 모른다 | AI 질문·에이전트도 사람과 같은 규칙으로 읽고, 누가 어떤 경로(화면·API·에이전트·AI 질문)로 무엇을 읽었는지 남는다 |
| 클라우드 데이터 서비스는 폐쇄망에 들어가지 못한다 | **설치본 하나**(Node·SQL 엔진·확장 포함)로 Windows·Linux 서버에 설치. 외부 호출 0건 |

## 구조

```mermaid
flowchart LR
    SRC["원본 연결<br/>Oracle · SQL Server · PG · MySQL<br/>Snowflake · REST · 폴더/S3"]
    FILE["파일<br/>CSV · 엑셀(보고서형도) · Parquet · JSON"]
    DOC["문서(비정형)<br/>Word · PDF · 한글 · 엑셀 · PPT · 스캔"]
    EVT["이벤트<br/>Kafka · HTTP · 변경 이력(CDC)"]
    subgraph LAKE["AX-DataLake"]
        ING["수집<br/>동기화 · 업로드 · 스트림"]
        DOCS["문서 수집 · 문서 → 표(AI)<br/>쓰기 전 개인정보 가림 · 검토 후 반영"]
        GOV["SQL 검사<br/>권한 · 열 가림 · 행 제한"]
        ONT["온톨로지 · 계보<br/>객체 · 관계 · 액션"]
        ENG["SQL 엔진<br/>조회(읽기 전용) · 작업 · 수집"]
    end
    CAT[("카탈로그<br/>SQLite · PostgreSQL")]
    DATA[("데이터 파일<br/>Parquet — 로컬 · NAS · S3 호환")]
    USR["사람<br/>웹 · SQL · BI"]
    AGT["AI 에이전트<br/>MCP · AI 질문"]
    SRC --> ING
    FILE --> ING
    EVT --> ING
    DOC --> DOCS
    ING --> ENG
    DOCS --> ENG
    USR --> GOV
    AGT --> ONT
    ONT --> GOV
    GOV --> ENG
    ENG --> CAT
    ENG --> DATA
```

- **저장과 계산을 나눈다.** 테이블 목록·시점(스냅샷)은 카탈로그에, 데이터는 공개 표준 Parquet 파일에 둔다. 카탈로그를 PostgreSQL·데이터를 S3 호환 저장소에 두면 서버를 여러 대 띄워 같은 레이크를 함께 쓴다.
- **시점 조회.** 테이블이 바뀔 때마다 시점이 남아, "어제 이 시각의 모습"이나 "두 시점 사이 바뀐 행"을 SQL 로 본다. 장애 원인 분석·감사에 쓴다.
- **엔진을 셋으로 나눠 잠근다.** 분석가 조회는 읽기 전용·파일 접근을 막은 엔진에서, 엔지니어 작업 SQL 은 레이크 폴더 안에서만 쓰는 엔진에서, 수집은 제품 코드만 쓰는 엔진에서 돈다.

## 기능

| 영역 | 내용 | 문서 |
|---|---|---|
| 수집 | 파일 올리기(EUC-KR CSV 자동 변환, 보고서형 엑셀 펴기 — XLSX·XLS, 시트 고르기), 원본 연결 동기화(Oracle·SQL Server·PostgreSQL·MySQL·Snowflake·REST API·폴더/S3(엑셀 포함), 주기 실행), Kafka·HTTP 실시간(붙이기·키로 바꾸기·변경 반영) | [수집](/datalake/ingest.md) |
| 문서(비정형) | Word·PDF·한글·엑셀·PPT·스캔(글자 인식)을 **쓰기 전에 개인정보를 가려** 조각 테이블로, 표 살리기, 낱말+의미 찾기, **문서 → 표(AI 추출)** — 견적서·계약서의 값을 사내 모델로 뽑아 검토 후 테이블에 | [문서(비정형)](/datalake/documents.md) |
| 분석 | **차트**(막대·선·면적·원·산점도·히트맵·숫자·피벗, 서버에서 다시 묶기)·**대시보드**(필터·초안/게시·보는 사람 권한·예약 발송·엑셀·포털)·**AI 분석**(지표·검증된 질의 근거, 이어 묻기)·**객체 분석**(세고 바로 액션) | [분석](/datalake/analysis.md) |
| 온톨로지 | 업무 객체·관계(열=열·조건식)·액션(메모·웹훅, 승인), ITO 표준 템플릿(유형 7·관계 11), 관계 그래프 | [온톨로지](/datalake/ontology.md) |
| 계보 | 원본 → 테이블 → 파생·뷰 → 객체 유형 → 소비 경로, 영향 범위 | [계보](/datalake/lineage.md) |
| 거버넌스 | 역할(관리자·데이터 엔지니어·분석가), 테이블 조회 권한, 열 가림, 행 제한, 감사·조회 이력 | [거버넌스](/datalake/governance.md) |
| 카탈로그 | 테이블 설명·담당·등급·태그·열 설명, 시점 이력, 바뀐 행, 미리 보기 | [거버넌스](/datalake/governance.md#카탈로그) |
| AI | 자연어 → SQL(플랫폼 게이트웨이, 기밀은 사내 모델만), 메타데이터 초안(개인정보 열 찾기·등급 권고·AI 설명), MCP 도구 14개(조회·시점·계보·객체 탐색·문서 찾기·말로 묻는 분석·액션 제안 — 같은 규칙) | [AI 질문과 에이전트](/datalake/ai.md) |
| 운영 | 폐쇄망 설치본(Windows·Linux 서비스), 매일 파일 정리, API 키(조회·수집·에이전트 범위) | [설치와 운영](/datalake/operations.md) |
