# AI 질문과 에이전트

AX-DataLake의 AI 기능은 사람이 말로 묻는 **AI 질문**, 카탈로그를 채우는 **메타데이터 초안**, AI 에이전트가 도구로 쓰는 **MCP** 다(문서에서 값을 뽑는 AI 추출은 [문서(비정형)](/datalake/documents.md)). 모두 [거버넌스](/datalake/governance.md)를 그대로 지난다 — AI 가 무엇을 쓰든 그 사람이 볼 수 없는 것은 보지 못한다.

## AI 질문 — 자연어 → SQL

SQL 작업창 위의 **AI 에게 묻기**에 "지난달 계열사별 수주 금액 합계"처럼 쓰면, 모델이 SQL 을 써서 실행하고 결과와 SQL 을 함께 보여 준다. 만든 SQL 은 작업창에 들어가 사람이 확인·수정해 다시 돌린다.

<figure><img src="img/datalake-ask.png" alt="AI 질문 — '상태별 주문 건수와 금액 합계'를 사내 모델이 SQL 로 써서 실행, 결과에 가림·행 제한 적용됨 표시"><figcaption>분석가(HD01)의 AI 질문. 사내 모델(<code>hnix-local</code>)이 SQL 을 쓰고, 결과는 행 제한이 적용된 HD01 주문만 집계한다.</figcaption></figure>

| 단계 | 하는 일 |
|---|---|
| 테이블 고르기 | 보는 사람이 볼 수 있는 테이블 중 질문과 가까운 것(이름·설명·태그) 8개까지 |
| 모델에 보내기 | **테이블·열 이름과 설명만** 보낸다. 데이터 값은 보내지 않는다. 가려진 열은 '가려진 값'으로 알려 조건·집계에 쓰지 않게 한다 |
| 모델 고르기 | AX Platform [LLM 게이트웨이](/platform/gateway.md)를 지난다. **기밀 등급 테이블이 섞이면 restricted 로 알려 사내 모델만** 쓴다 |
| 실행 | 사람이 쓴 SQL 과 같은 검사 — 쓰기 SQL 이면 막히고, 권한·가림·행 제한이 걸린다 |
| 고쳐 쓰기 | SQL 오류가 나면 오류를 모델에 보여 주고 한 번 다시 쓰게 한다(권한 거부는 고치지 않는다) |
| 기록 | 조회 이력에 질문과 함께, 게이트웨이 요청 기록에 모델·토큰 |

설정: `ai.gateway` 에 플랫폼 게이트웨이 주소와 가상 키(llm 권한)를 넣는다. 비워 두면 기능이 꺼지고 버튼이 보이지 않는다.

## 메타데이터 초안 — 개인정보 열 찾기 · 등급 권고 · AI 설명

카탈로그에서 테이블을 열고 **AI 설명 초안**(데이터 엔지니어·관리자)을 누르면:

| 단계 | 하는 일 |
|---|---|
| 개인정보 열(규칙, AI 없이) | 가림이 없는 열에서 값 형식(주민등록번호·전화·이메일·카드·주소)과 열 이름(이름·계좌·연락처…)으로 찾고 근거("표본 40개 중 40개가 전화번호 형식")를 보인다 |
| 등급 권고 | 주민번호·카드·계좌가 있으면 기밀, 그 밖의 개인정보는 대외비(올리기만, 내리지 않는다) |
| 설명·용어(AI, 선택) | 테이블 구조와 열마다 표본 값 3개를 게이트웨이 모델에 보내 설명·태그·열 설명·업무 용어 초안을 받는다. **개인정보로 본 열은 값을 보내지 않는다** |
| 반영 | 화면에서 고른 것만. 열 가림은 관리자만. 초안·반영 모두 감사 기록에 |

거버넌스의 '개인정보 열 찾기'는 같은 규칙으로 모든 테이블을 훑어 가림 없는 개인정보 열을 모아 보이고, 관리자가 바로 부분 가림을 건다. 문서(비정형)에서 값을 뽑아 표로 만드는 것은 [문서(비정형)의 문서 → 표(AI 추출)](/datalake/documents.md).

## MCP — 에이전트가 레이크를 쓴다

`/mcp`(Streamable HTTP). '에이전트(MCP)' 범위 API 키로 붙고, **키 주인의 권한·가림·행 제한이 그대로** 걸린다.

| 도구 | 하는 일 |
|---|---|
| `list_tables` | 볼 수 있는 테이블(설명·등급·태그) |
| `describe_table` | 열·타입·설명, 이 사용자에게 가려지는 열, 행 제한 여부 — SQL 을 쓰기 전에 부른다 |
| `query` | SELECT 한 문장(최대 200행). 거부·오류도 에이전트가 읽고 고칠 수 있게 결과로 돌려준다 |
| `table_history` | 테이블이 바뀐 시점 |
| `table_changes` | 두 시점 사이 바뀐 행 — "장애 직전에 무엇이 바뀌었나" |
| `table_lineage` | 테이블이 어디서 와서 어디로 가나 — [계보](/datalake/lineage.md) |
| `ontology_types` · `find_objects` · `get_object` · `linked_objects` | 업무 객체를 SQL 없이 — 장애 → 직전 72시간 변경 → 요청자. [온톨로지](/datalake/ontology.md) |
| `list_document_collections` · `search_documents` | 볼 수 있는 [문서 묶음](/datalake/documents.md)과 문서 조각 찾기(낱말 + 의미) — 근거로 문서·제목 경로를 준다. 조각은 수집 때 개인정보를 가린 것 |
| `propose_action` | 객체에 액션 제안 — 메모는 바로, 웹훅은 사람 승인 뒤(유일하게 읽기 전용이 아닌 도구) |

붙이는 곳:

| 쓰는 곳 | 방법 |
|---|---|
| AX Platform MCP 허브 | 외부 MCP 서버로 등록(`datalake__*` 도구) → 관리자 승인 → 허브의 정책·승인·감사 아래에서 경보 진단 에이전트·AX-NAVI·Claude Code 가 쓴다 |
| Claude Code 직접 | `claude mcp add --transport http ax-datalake http://서버:8790/mcp --header "X-API-Key: axdl_…"` |

> 허브에 등록할 때 쓰는 키의 주인이 곧 에이전트의 권한이다. 운영 분석용이면 분석가 계정의 키를 써서 가림·행 제한이 걸린 데이터만 보게 한다.

## 장애 분석에 쓰는 예

1. 경보 진단 에이전트가 허브로 `datalake__query` — "최근 1시간 이 시스템의 오류 로그 건수와 상위 메시지".
2. `datalake__table_changes` — 장애 직전 설정·코드 테이블에서 바뀐 행.
3. 결과를 근거로 원인 후보를 PMS-X 장애에 남긴다. 개인정보는 가린 값으로만 지나간다.
