# AI 질문과 에이전트

AX-DataLake의 AI 기능은 두 가지다. 사람이 말로 묻는 **AI 질문**과, AI 에이전트가 도구로 쓰는 **MCP**. 둘 다 [거버넌스](/datalake/governance.md)를 그대로 지난다 — AI 가 무엇을 쓰든 그 사람이 볼 수 없는 것은 보지 못한다.

## AI 질문 — 자연어 → SQL

SQL 작업창 위의 **AI 에게 묻기**에 "지난달 계열사별 수주 금액 합계"처럼 쓰면, 모델이 SQL 을 써서 실행하고 결과와 SQL 을 함께 보여 준다. 만든 SQL 은 작업창에 들어가 사람이 확인·수정해 다시 돌린다.

| 단계 | 하는 일 |
|---|---|
| 테이블 고르기 | 보는 사람이 볼 수 있는 테이블 중 질문과 가까운 것(이름·설명·태그) 8개까지 |
| 모델에 보내기 | **테이블·열 이름과 설명만** 보낸다. 데이터 값은 보내지 않는다. 가려진 열은 '가려진 값'으로 알려 조건·집계에 쓰지 않게 한다 |
| 모델 고르기 | AX Platform [LLM 게이트웨이](/platform/gateway.md)를 지난다. **기밀 등급 테이블이 섞이면 restricted 로 알려 사내 모델만** 쓴다 |
| 실행 | 사람이 쓴 SQL 과 같은 검사 — 쓰기 SQL 이면 막히고, 권한·가림·행 제한이 걸린다 |
| 고쳐 쓰기 | SQL 오류가 나면 오류를 모델에 보여 주고 한 번 다시 쓰게 한다(권한 거부는 고치지 않는다) |
| 기록 | 조회 이력에 질문과 함께, 게이트웨이 요청 기록에 모델·토큰 |

설정: `ai.gateway` 에 플랫폼 게이트웨이 주소와 가상 키(llm 권한)를 넣는다. 비워 두면 기능이 꺼지고 버튼이 보이지 않는다.

## MCP — 에이전트가 레이크를 쓴다

`/mcp`(Streamable HTTP). '에이전트(MCP)' 범위 API 키로 붙고, **키 주인의 권한·가림·행 제한이 그대로** 걸린다.

| 도구 | 하는 일 |
|---|---|
| `list_tables` | 볼 수 있는 테이블(설명·등급·태그) |
| `describe_table` | 열·타입·설명, 이 사용자에게 가려지는 열, 행 제한 여부 — SQL 을 쓰기 전에 부른다 |
| `query` | SELECT 한 문장(최대 200행). 거부·오류도 에이전트가 읽고 고칠 수 있게 결과로 돌려준다 |
| `table_history` | 테이블이 바뀐 시점 |
| `table_changes` | 두 시점 사이 바뀐 행 — "장애 직전에 무엇이 바뀌었나" |

붙이는 곳:

| 쓰는 곳 | 방법 |
|---|---|
| AX Platform MCP 허브 | 외부 MCP 서버로 등록(`datalake__*` 도구) → 관리자 승인 → 허브의 정책·승인·감사 아래에서 경보 진단 에이전트·AX-NAVI·Claude Code 가 쓴다 |
| Claude Code 직접 | `claude mcp add --transport http ax-datalake http://서버:8790/mcp --header "X-API-Key: axdl_…"` |

> 허브에 등록할 때 쓰는 키의 주인이 곧 에이전트의 권한이다. 운영 분석용이면 분석가 계정의 키를 써서 가림·행 제한이 걸린 데이터만 보게 한다.

## 장애 분석에 쓰는 예

1. 경보 진단 에이전트가 허브로 `datalake__query` — "최근 1시간 이 시스템의 오류 로그 건수와 상위 메시지".
2. `datalake__table_changes` — 장애 직전 설정·코드 테이블에서 바뀐 행.
3. 결과를 근거로 원인 후보를 PMS-X 장애에 남긴다. 개인정보는 가린 값으로만 지나간다.
