# 거버넌스 — 권한 · 열 가림 · 행 제한

AX-DataLake의 거버넌스는 **SQL 을 실행하기 전에** 건다. 화면의 SQL 작업창, API 키로 붙은 BI·스크립트, MCP 로 붙은 AI 에이전트, AI 질문이 만든 SQL — 어느 길로 들어와도 같은 검사를 지난다.

## 역할

| 역할 | 볼 수 있는 것 | 할 수 있는 것 |
|---|---|---|
| 관리자 | 모든 테이블, 원문 | 사용자·원본 DB 연결·거버넌스·파일 정리 |
| 데이터 엔지니어 | 모든 테이블(가림·행 제한은 정책대로) | 수집(파일·원본 DB·스트림), 작업 SQL(테이블·뷰 만들기·고치기), 테이블 설명 |
| 분석가 | **조회 권한을 준 테이블만** | 조회(SELECT), AI 질문, 내 API 키 |

## SQL 검사

사용자가 보낸 SQL 을 SQL 엔진이 만든 **구조(구문 트리)로 풀어서** 본다. 글자 검사가 아니라 별칭·WITH·하위 조회·JOIN 어디에 숨겨도 같은 결과다.

| 검사 | 막는 것 |
|---|---|
| 한 문장, SELECT 만 | 쓰기·삭제·설정 변경·파일 복사, 여러 문장 이어 붙이기 |
| 레이크 테이블만 | 시스템 카탈로그·제품 내부 스키마·다른 DB 붙이기 |
| 파일·외부 함수 금지 | 서버 파일 직접 읽기(`read_csv` 등), 파일 경로를 테이블처럼 쓰기 |
| 조회 권한 | 권한 없는 테이블 — "볼 권한이 없습니다"로 거절하고 이력에 '거부'로 남긴다 |

검사를 지난 SQL 에서 정책이 걸린 테이블은 **가린 하위 조회로 바꿔 끼운다.** 원래 이름(별칭)은 그대로라 사용자가 쓴 SQL 은 바뀌지 않는다. 시점 조회(`AT (VERSION => …)`)를 써도 가림이 따라간다.

**이중 방어** — 조회 엔진 자체가 읽기 전용으로 붙어 있고 파일 접근·설정 변경이 잠겨 있다. SQL 검사를 빠져나가는 길이 있더라도 쓰기·서버 파일 읽기는 되지 않는다.

## 열 가림

| 종류 | 부분 가림 예 |
|---|---|
| 주민등록번호 | `900101-1******` |
| 전화번호 | `010-****-5678` |
| 이메일 | `h***@example.co.kr` |
| 카드번호 | `1234-****-****-5678` |
| 계좌번호 | `********5678` |
| 이름 | `홍*동` |
| 주소 | `서울시 강남구 ***` |

- 가림 방식: 부분 가림(위 형식) · 전체 가림(`****`) · 해시(같은 값끼리는 묶여 집계·조인 가능) · 비움(NULL).
- **형식이 맞지 않는 값은 통째로 가린다** — 형식이 다르다고 원문이 새지 않게.
- 열마다 원문을 볼 역할을 정한다(기본: 관리자만).

## 행 제한

조건은 SQL 식이다. `:org` 는 **보는 사람의 소속**(사용자 화면의 '소속')으로 바뀐다.

```sql
company_code = :org
```

- 소속이 없는 사람에게는 아무 행도 보이지 않는다(실수로 전부 보이지 않게).
- 한 테이블에 조건을 여러 개 걸면 모두 만족하는 행만 보인다.
- 제한을 받지 않는 역할을 정한다(예: 관리자·데이터 엔지니어).
