# 프로젝트 관리와 협업

일정·인력·품질·산출물을 As-Is 화면 자산과 같은 시스템에서 다룬다. 테스트 케이스는 화면·버튼에, 결함은 테스트 절차에, 위키 페이지는 요구사항에 이어진다.

## PM 대시보드와 공지사항

홈은 역할별 대시보드다. PM 대시보드에는 진척·SPI·미해결 이슈·결함·MM 카드 아래에 다음이 이어진다.

- **공지사항** — 게시 중인 최근 5건, 고정 공지가 먼저.
- **공정현황** — 공정준수율, 계획/실적 진척, 업무별 공정준수율.
- **이슈현황**과 업무별 일감진척 카드.
- **일감진행추이** — 주별 계획·실적 막대와 누적 계획·실적·예측 선, 업무별 주단위·누적 표.

<figure><img src="img/pmsx-home-pm.png" alt="PM 대시보드 — 진척, 일정 성과 지수(SPI), 공지사항, 진척 곡선"><figcaption>PM 대시보드 — 진척 카드와 공지사항, 진척 곡선</figcaption></figure>

**공지사항** 화면은 프로젝트 공지를 관리한다. 본문은 Markdown이고, 상단 고정과 게시 종료일을 둔다. 게시 종료일이 지난 공지는 대시보드에서 빠진다. 작성은 PM · PL · 관리자, 조회는 프로젝트 멤버 전원이다.

## WBS와 공정준수율

영업일 기준 CPM 핵심 경로(크리티컬 패스), 선후행 FS/SS/FF/SF, 드래그 일정 변경을 지원한다. 행마다 **계획 진척과 공정준수율**을 표시한다.

| 등급 | 기준 | 색 |
|---|---|---|
| 양호 | 공정준수율 100% 이상 | 초록 |
| 보통 | 95% 이상 | 파랑 |
| 미흡 | 95% 미만 | 주황 |
| 착수 지연 | 계획 시작일이 지났는데 착수 전 | 분홍 |
| 종료 지연 | 계획 종료일이 지났는데 미완료 | 빨강 |

- **기준일** — 어느 날짜 기준으로 계획 진척을 계산할지 고른다.
- **비교할 베이스라인** — **보기** 메뉴에서 저장해 둔 베이스라인을 골라 그 시점 계획과 비교한다.
- **필터** 메뉴 — 마일스톤 · 내 작업만 · 완료 작업 숨김 · 일정 충돌 작업. 켠 개수가 버튼에 붙는다.

### 간트 보기

표 위의 **보기 줄**(**보기** 메뉴 — 배치·촘촘히·베이스라인·핵심 경로 — 와 단위·확대·기준일·**필터** 메뉴·크게 보기)과 **편집 줄**(작업 추가·들여쓰기·저장 등)을 나눴다. 보기 설정은 브라우저가 기억한다.

| 하고 싶은 것 | 방법 |
|---|---|
| 표와 간트 비율 (보기 메뉴) | **나란히**(경계를 끌어 폭 조절) · **표 크게**(간트를 감추고 모든 칸) · **간트 크게**(번호·작업명만 남기고 나머지는 간트) |
| 화면 전체로 | **크게 보기** — WBS 카드가 화면을 덮고 표·간트 높이를 화면에 맞춘다. **Esc** 로 돌아온다 |
| 확대·축소 | 단위 **일 · 주 · 월 · 분기**, **+ / −** 단추나 키, **Ctrl+휠**(마우스가 있는 날짜를 기준으로). 눈금 두 줄이 단계에 맞춰 월/일·주, 연/월·분기로 바뀐다 |
| 한눈에 / 오늘로 | **전체 보기**는 전체 일정을 한 화면에, **기준일로**는 기준일 위치로 옮긴다 |
| 화면 옮기기 | 간트의 빈 곳을 끌면 움직이고, 누르면 그 행을 고른다. 표에서 고른 행은 간트가 막대 위치로 따라간다 |
| 막대 정보 | 막대에 마우스를 올리거나 키보드로 초점을 주면 카드 — 기간 · 영업일 · 진척 · 담당 · 베이스라인과 차이(○일 늦음/빠름) · 핵심 경로. 막대를 끄는 동안에는 놓으면 바뀔 날짜를 보여 준다. 막대에서 **← / →** 로 일정을 옮긴다 |
| 쉬는 날 | 주말·공휴일은 음영으로, 머리 눈금에 기준일 표시 |
| 더 많은 행 | **보기 › 촘촘히** — 행 높이를 30px 로 줄인다. 표와 간트의 행은 그대로 맞는다 |

### 엑셀처럼 작성하기

WBS 표는 칸을 바로 고치는 방식이다. 저장 버튼을 누르기 전까지는 화면 안의 사본이라, **초기화**로 언제든 되돌린다.

| 하고 싶은 것 | 방법 |
|---|---|
| 기간으로 일정 잡기 | **기간** 칸에 영업일 수를 쓰면 종료일이 주말·공휴일(공통코드 `HOLIDAY`)을 건너 계산된다. 시작일을 옮기면 기간을 지킨 채 종료일이 따라간다. 0 은 마일스톤 |
| 선후행 걸기 | **선행** 칸에 WBS 번호를 쓴다 — `1.2`(끝나면 시작), `1.3SS+2`(시작 2일 뒤 시작), 쉼표로 여러 개. 엑셀 가져오기와 같은 형식이고, 없는 번호·순환은 막는다 |
| 빠르게 입력 | **Enter** 아래 칸 · **Shift+Enter** 위 칸 · **Esc** 입력 취소. 마지막 행 작업명에서 Enter 는 새 작업 |
| 계층 바꾸기 | **Alt+Shift+→/←** 들여쓰기·내어쓰기, **Alt+Shift+↑/↓** 위아래 이동(MS Project 와 같은 키) |
| 여러 행 한꺼번에 | **Ctrl·Shift 클릭**으로 고른 뒤 들여쓰기·내어쓰기·이동·삭제·담당자 지정 |
| 담당자 | **담당** 칸을 누르면 프로젝트 인원 중에서 고른다 |
| 목록 한 번에 넣기 | 엑셀·메모장에서 여러 줄을 복사해 작업명 칸(빈 표면 표)에 붙여 넣는다. 앞의 탭·공백 2칸은 하위 작업, 날짜 칸은 시작·종료, 숫자 칸은 기간으로 읽는다. 첫 칸이 `1.2.1` 같은 번호면 그 깊이를 따른다 |
| 화면 나누기 | '나란히'에서 표·간트 경계를 끌어 폭을 바꾼다(브라우저가 기억). 가로로 넘겨도 번호·작업명 열은 고정 |

## 인력 편성과 작업 배분

**인력·공수 → 인력 편성 / 투입 계획**에서 프로젝트 인원을 꾸린다. 관리 메뉴로 가지 않고 이 표에서 인원을 추가·수정·제외한다.

- **인원 추가** — 사용자 · 프로젝트 역할 · 투입일 · 철수일. 투입 기간은 프로젝트 기간으로 미리 채워진다.
- **투입 기간으로 MM 채우기** — 인원을 추가하거나 투입 기간을 바꾸면 그 달 영업일 중 투입한 날의 비율로 월 MM 이 채워진다(0.1 MM 단위, 주말·공휴일 제외). 칸을 직접 고칠 수도 있고, **투입 기간으로 모두 채우기**로 전원을 다시 계산한다.
- **투입 계획률(MM 기준)** — 다른 프로젝트까지 합친 월 계획 MM 을 비율(1.0 MM = 100%)로, 월·주 단위 색으로.

<figure><img src="img/pmsx-staffing.png" alt="인력 편성 — 인원·역할·투입 기간·월 MM 한 표"><figcaption>인력 편성 — 인원 · 역할 · 투입 기간 · 월 MM 을 한 표에서, 행마다 수정 · MM 채우기 · 제외</figcaption></figure>

**작업 배분**은 미배정 작업을 사람에게 끌어 놓아 맡긴다. WBS 작업과 As-Is 화면 분석을 탭으로 나누고, 마일스톤은 배정 대상에서 뺀다. 오른쪽 **작업 배정률(작업 기준)**은 계획 기간이 겹치는 WBS 작업의 배정 비율을 다른 프로젝트까지 합친 값이고, 배정하기 전에 작업 기간 중 100% 를 넘는 주가 생기면 경고한다.

## 일감 칸반

WBS 작업 · 이슈 · 결함 · 변경요청을 **한 보드**에 모은다.

- 열은 **프로젝트별 워크플로우 단계**다. 예: 등록 → 매핑 정의 → AI설계검토 → 개발 → 진행.
- 유형 칩과 단계 칩(분석 · 설계 · 구현 · 시험 · 이행 · 단계 없음)으로 거른다. 열 구성은 **단계 흐름 설정**에서 바꾼다.
- 카드를 끌면 각 유형의 전이 규칙과 권한을 그대로 거쳐 상태가 바뀐다. 결함을 권한 없이 "종료"로 옮길 수는 없다.
- 카드를 열면 **일감 상세 패널** — 담당자, 계획일자, 현재 단계와 처리 이력, 첨부, 상세, 추적 연결, 댓글. 이슈 · 결함 · 변경요청 화면에서도 같은 패널을 쓴다.

## 테스트 절차와 결함

테스트 케이스는 차수별로 관리하고, 케이스마다 **순서 있는 절차**(절차명 · TC 데이터 · 예상결과 · 실제결과 · 상태)를 둔다.

- 실패한 절차는 확인 후 **결함을 자동 등록**해 그 절차 아래에 연결한다.
- 목록과 상단에 절차 요약 — 전체 · 실적% · 성공% · 실패 · 진행 불가.

<figure><img src="img/pmsx-tests.png" alt="테스트 — 시나리오·케이스와 절차 요약"><figcaption>테스트 — 시나리오별 케이스, 케이스마다 절차 실적, 상단 절차 요약</figcaption></figure>

**회의록**에는 액션아이템 표(No · Action Item · 담당 · 완료예정일 · 상태 · 비고)가 붙는다.

## 프로젝트 위키

산출물 대장에 넣기엔 가볍고 메신저에 두기엔 남겨야 하는 지식 — 개발 표준, 환경 정보, 회의 결정 배경 — 을 위키에 쓴다.

- 공간 여러 개, 페이지 트리, Markdown 편집 + 미리보기, 목차.
- **버전 이력** — 보기 · 비교 · 복원. 동시 편집 충돌을 감지한다.
- 댓글, 즐겨찾기, 지켜보기 알림.
- 이미지는 첨부 파일로만 넣는다. 외부 URL은 쓰지 않으므로 폐쇄망에서도 깨지지 않는다.
- 요구사항 · 추적성 매트릭스에서 위키 페이지로 연결된다.

## 고객 승인함

구축(SI) 프로젝트의 고객도 **고객 요청 창구**로 들어온다. 창구 위의 **승인함** 탭에 고객 승인이 필요한 일이 모이고, 처리할 건수가 배지로 붙는다. 운영(SM) 프로젝트 없이 SI 프로젝트에만 고객으로 참여한 사람은 승인함이 첫 화면이다.

| 묶음 | 고객이 하는 일 |
|---|---|
| 승인할 산출물 | 고객 승인 대상으로 검토 요청된 산출물을 파일과 함께 보고 **승인 / 반려**. 승인하면 담당자에게 알림이 가고 연결된 WBS 작업이 완료로 바뀐다 |
| 승인할 변경요청 | 영향을 산정한 변경요청(범위·공수·일정 변화)을 보고 **승인 / 반려**. 반려 사유는 담당자에게 그대로 간다 |
| 주간보고 | **제출된** 주간보고만 읽는다(프로젝트마다 최근 8건). 작성 중인 초안은 고객에게 보이지 않는다 |

- 고객으로 참여한 프로젝트만 보이고, 승인·반려는 내부 화면과 같은 권한 검사를 거친다. 이미 다른 사람이 처리한 항목이면 알리고 목록을 새로 불러온다.
- API: `GET /api/v1/portal/approvals`.

## 목록과 빈 화면

- **건수가 맞는 필터** — 이슈 '미해결만', 서비스 요청 '진행 중만'은 서버에서 걸러 목록과 건수가 같다.
- **빈 화면 안내** — 목록이 비면 무엇을 등록하면 되는지, 필터 때문에 비었으면 어떤 조건을 끄면 더 보이는지 알려 준다.
- **기한 지남** — 색만이 아니라 아이콘과 '지남' 글자로 표시한다.
- **없는 주소** — "페이지를 찾을 수 없습니다" 화면에서 **홈으로** · **이전 화면**.
