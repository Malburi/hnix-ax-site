# DB · PL/SQL 분석

레거시 업무 로직의 절반은 DB 안에 있다. 화면이 부르지 않아도 트리거가 이력을 쓰고, 패키지가 마감을 돌린다. PMS-X는 DB 오브젝트까지 수집해 화면 분석과 같은 그래프에 잇는다.

## 무엇을 모으나

수집기는 테이블·컬럼·인덱스·FK에 더해 **트리거 · 뷰 · 패키지(명세+본문) · 프로시저 · 함수 · 시퀀스 · 시노님**을 모은다.

- Oracle · Tibero · PostgreSQL · SQL Server · MySQL의 사전 뷰를 **읽기 전용**으로 조회한다.
- DB에 붙을 수 없는 환경이면 DDL 파일로도 된다.
- 트리거와 뷰 본문은 SQL 추출기를 거쳐 **테이블 연결선**이 된다. 그래서 "이 화면의 수정이 어떤 트리거를 거쳐 어느 테이블에 쓰는가"를 뷰어의 [트리거 탭](/pmsx/asis.md)에서 볼 수 있다.

## DB 오브젝트

계정(스키마)별 종류 트리와 건수, 하이라이트된 원본 소스, 그 오브젝트가 **참조하는** 것과 **참조되는** 것을 한 화면에 보여 준다.

## 테이블 정의서와 상세

테이블 목록에는 **품질 배지**가 붙는다 — PK 없음 · CHAR 사용 · 코멘트 없음 · PL/SQL 참조 수 · 사용 화면 수. 정리 대상 테이블이 목록에서 바로 보인다.

<figure><img src="img/pmsx-tables.png" alt="테이블 정의서 — 품질 배지"><figcaption>테이블 정의서 — CHAR 사용, PL/SQL 참조, 사용 화면 수 배지</figcaption></figure>

테이블을 고르면 상세가 열린다.

| 탭 | 보여 주는 것 |
|---|---|
| 컬럼 | 컬럼 정의와 연결된 **표준 용어** |
| 인덱스 · 관계 | 인덱스, FK, 추정 관계 |
| 확인할 화면 | 이 테이블을 바꾸면 확인해야 할 화면 — **직접 SQL / 트리거 경유 / 프로시저 경유**로 나눠 보여 주고 Excel로 낸다 |
| 참조 오브젝트 | 이 테이블을 쓰는 트리거 · 뷰 · 패키지 · 프로시저 |
| DDL | 수집한 메타로 재구성한 DDL |

"확인할 화면"은 테스트 범위를 정할 때 쓴다. 직접 SQL만 보면 놓치는 화면 — 트리거나 프로시저를 거쳐 같은 테이블에 닿는 화면 — 까지 목록에 들어간다.

## ERD

FK가 없는 레거시 DB도 SQL의 JOIN 패턴으로 테이블 관계를 추정해 점선으로 그리고, 분석자가 확정하거나 기각한다.

- **보는 범위** — 주제영역, 테이블 직접 선택, **메뉴 기준**(메뉴 폴더 아래 화면들이 읽고 쓰는 테이블).
- **엔터티 분류** — 기본 · 중심 · 행위 · 코드 · 일반을 색과 범례로 구분한다.
- **관계** — FK는 실선, 추정 관계는 점선과 신뢰도.

## 검색과 영향도

- **통합 검색 (Ctrl+K)** — 요구사항 · WBS · 이슈 · 결함 · 테스트 · 산출물 · SR · KB · 화면에 더해 **테이블 · 컬럼 · 프로시저 · 트리거**까지 찾는다.
- **영향도 분석** — 테이블 · 컬럼 · 함수 → 영향 화면 · 버튼 · 배치 · 최근 SR · 담당자를 경로와 함께 보여 준다. MCP 도구 `pmsx__impact`로도 쓴다.
