# SM 운영과 AI 보조

PMS-X의 SM 운영은 서비스 요청·장애·문제·변경·배포·정기 작업·지식 문서·처리 기한·월간 운영보고·고객 요청 창구를 다룬다. 처리 기한은 업무시간과 공휴일을 반영해 계산하고, 요청마다 남은 시간과 임박·초과를 보여 준다. 여기에 경보 접수와 AI 보조 기능이 더해졌다.

## SM 프로젝트 홈

운영 프로젝트를 고르면 홈이 운영 카드로 바뀌고, 왼쪽 메뉴의 **운영**이 홈·공지사항 바로 아래로 올라와 펼쳐진다.

| 카드 | 보여 주는 것 |
|---|---|
| 운영 현황 | 이번 달 처리 기한 준수율, 진행 중 요청 · 처리 기한 임박 · 지금 기한 초과(미종료 전체) · 진행 중 장애 |
| 운영 카드 | 이번 달 응답 기한 준수율(기준 건수 — "이번 달 접수 n건 기준") · 만료 임박 자산 · 오늘 남은 정기 작업 · 열린 경보 · 문제 후보 |
| 처리 기한 준수율 추이 | 최근 6개월, 월별 접수된 서비스 요청 기준. 접수가 없던 달은 0% 가 아니라 비워 둔다 |
| 처리 중인 서비스 요청 | 지금 열려 있는 요청(번호·우선순위·상태·제목, 누르면 그 요청), 진행 중 장애 n건(누르면 장애 화면) |

대상이 0건이면 0% 대신 **대상 없음**으로 적는다 — 요청이 없는 달이 "준수율 0%"로 보고되지 않는다. 처리 기한 화면과 월간 운영보고(요약 문장·엑셀)도 같다.

### 메뉴와 고객 요청 창구

- SM 프로젝트 메뉴에는 품질 › 변경요청이 없다. 운영 변경은 **운영 › 변경 요청**(CAB 승인·배포)에서 하고, CAB(변경 심의)가 무엇인지 화면에 설명이 붙는다. 구축 변경요청은 SI 프로젝트에서만 보인다.
- 알림 설정은 관리 메뉴가 아니라 오른쪽 위 **사용자 메뉴**에서 연다.
- **고객 요청 창구**(고객 포털)는 휴대폰 폭에서 표 대신 카드 목록(번호·상태·접수 시각·제목·유형·화면)으로 보인다. SI 프로젝트 고객에게는 승인함 탭이 함께 나온다 — [고객 승인함](/pmsx/pm.md#고객-승인함).
- 지식 문서 목록의 태그는 한글 유형 이름으로, 운영 자산은 만료까지 남은 기간("12일 남음", "오늘 만료")으로 보인다.

## 업무 템플릿

요청·장애·변경을 사람마다 다르게 처리하지 않도록, 처리 절차를 템플릿으로 둔다. 메뉴 **운영 › 업무 템플릿**.

| 기본 템플릿 | 절차 (요약) |
|---|---|
| 장애 대응 | 접수·등급 판정 → 1차 보고(1등급 15분) → 영향 범위 → 임시 조치 → 원인 분석 → 항구 조치(변경 등록) → 장애 보고서 → 재발 방지·지식 문서 |
| 변경·배포 | 영향 분석 → 테스트 결과 → 롤백 계획 → CAB 승인 → 배포 공지 → 배포·확인 → 산출물 현행화 |
| 요청(문의 · 데이터 수정 · 기능 개선 · 권한 · 오류 신고) | 요청 유형별 절차 — 예: 데이터 수정은 승인 문서 확인 → 건수 확인 → 백업 → 2인 확인 → 실행 → 결과 확인 |

- 프로젝트에 템플릿이 없으면 기본 템플릿을 보여 주고, "기본 템플릿 가져오기"로 복사해 고객사 기준에 맞게 고친다.
- 요청·장애·변경 상세의 **처리 절차** 칸에서 템플릿을 고르면(요청은 유형에 맞는 템플릿이 먼저 골라져 있다) 체크리스트로 진행한다. 완료 처리자와 시각은 서버가 기록한다.
- 템플릿의 절차 순서는 [인수인계 퀴즈](/pmsx/handover.md#인수인계-이해도-퀴즈)의 출제 근거로도 쓰인다.

## 경보 접수

모니터링 도구(Zabbix, Prometheus Alertmanager 등)가 보낸 경보를 장애나 요청으로 만든다.

<figure><img src="img/pmsx-alerts.png" alt="장애 화면 상단의 경보 목록과 자동 생성된 장애"><figcaption>경보 목록. 같은 경보는 하나로 묶이고(×2) 장애·요청으로 이어진다.</figcaption></figure>

```bash
POST /api/v1/projects/{projectId}/alerts          # 한 건
POST /api/v1/projects/{projectId}/alerts/batch    # 여러 건 (Alertmanager 웹훅처럼)
```

| 심각도 | 처리 |
|---|---|
| critical | 장애 1등급 |
| major | 장애 2등급 |
| minor | 요청(장애 유형) P2 |
| warning | 요청 P3 |
| info | 기록만 |

- 같은 (프로젝트·출처·지문) 경보가 열려 있으면 새로 만들지 않고 횟수와 마지막 시각만 올린다. 요청 수준으로 열린 경보가 장애 수준으로 올라오면 그때 장애를 만든다(격상).
- 해소(resolved)는 장애 복구 시각과 타임라인, 요청 내부 코멘트로 남긴다. 종료와 원인 분석(RCA)은 사람이 한다.
- 별도 API 키를 쓰지 않는다. 운영 역할(PM·PL·OPERATOR)을 가진 서비스 계정으로 로그인해 보낸다.

## AI 보조 — 켤 때만

AI 기능은 기본으로 꺼져 있다. 켜면 AX Platform 게이트웨이(OpenAI 호환)로만 호출한다. 끈 상태에서는 외부 호출이 0건이다.

```yaml
pmsx:
  ai:
    enabled: ${PMSX_AI_ENABLED:false}
    base-url: ${PMSX_AI_BASE_URL:}        # 예: http://ax-platform:8700/v1
    api-key: ${PMSX_AI_API_KEY:}          # 게이트웨이 llm 키
    model: ${PMSX_AI_MODEL:hnix-smart}
    data-class: ${PMSX_AI_DATA_CLASS:internal}   # restricted 면 게이트웨이가 로컬 모델만 쓴다
```

화면에는 어떤 모델 별칭으로 만든 결과인지가 늘 표시된다.

### 서비스 요청 분류·배정 추천

<figure><img src="img/pmsx-sr-triage.png" alt="요청 상세의 분류·배정 추천 패널"><figcaption>유형·우선순위·대상 화면·담당자 추천. 칸마다 "AI 선택"·"규칙 1순위" 근거 표시와 반영 버튼.</figcaption></figure>

- PMS-X가 먼저 후보를 결정론적으로 좁힌다: 코드 목록, 화면 그래프, 비슷한 요청, 화면 담당자.
- 모델은 그 **후보 안에서만** 고르고 이유를 적는다. 목록 밖 값은 받아들이지 않는다.
- 운영자가 확인하고 **반영**해야 저장된다.

### 유사 사례와 지식 문서 초안

<figure><img src="img/pmsx-kb-draft.png" alt="끝난 요청에서 만든 지식 문서 초안 대화상자"><figcaption>끝난 요청의 본문과 처리 코멘트를 요약한 지식 문서 초안. 출처 요청 번호가 끝에 남는다.</figcaption></figure>

처리가 끝난 요청에서 증상·원인·처리 내용·재발 방지·관련 사례로 정리한 초안을 만든다. 사실을 확인하고 등록하면 다음 요청에서 유사 사례로 추천된다.

### 버튼·함수 설명 초안과 근거 등급

<figure><img src="img/pmsx-ai-desc.png" alt="조회 버튼 설명 탭의 근거 충분 등급과 AI 초안 만들기 버튼"><figcaption>설명 탭. 근거 등급과 근거 흐름, AI 초안 만들기 · 직접 작성 버튼이 함께 보인다.</figcaption></figure>

As-Is 뷰어의 버튼·함수에 설명 초안을 만든다. 근거는 수집기가 만든 워크플로우(이벤트 → 함수 → SQL → 테이블)와 그 연결의 신뢰도다.

| 등급 | 뜻 |
|---|---|
| 녹색 · 근거 충분 | 흐름이 테이블까지 이어지고 모든 연결의 신뢰도가 0.8 이상 |
| 황색 · 근거 일부 | 확정되지 않은 저신뢰 연결이 있거나 흐름이 중간에서 끊긴다. 초안에 확인할 점이 함께 적힌다 |
| 적색 · 근거 부족 | 흐름이 없다. 초안을 믿지 말고 화면 담당자에게 확인한다 |

초안은 **확정**을 눌러야 산출물에 쓰인다. 소스가 다시 수집되어 흐름이 바뀌면 "다시 확인 필요"로 표시된다.

## 용어 사전과 관계

<figure><img src="img/pmsx-term-relations.png" alt="용어 사원의 동의어와 연결된 화면, 추천 테이블·컬럼"><figcaption>용어 "사원" — 동의어, 연결된 화면 3개, 추천 테이블과 컬럼</figcaption></figure>

- 용어마다 동의어를 둔다(예: 사원 — 직원, 임직원, 사번).
- 시스템별로 화면·테이블·컬럼과 연결한다. 이름과 컬럼 코멘트가 일치하는 대상을 추천하고, 사람이 확인한 것만 연결한다.
- 요청 본문에 동의어가 쓰여도 같은 화면과 테이블로 찾아간다.
